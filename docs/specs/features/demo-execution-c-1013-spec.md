## 1. Инварианты (нарушение любого — остановка новых входов и запись тревоги)

1. **Ни одна позиция не живёт без защитного ордера на бирже дольше
   `TRADING_MAX_UNPROTECTED_SEC = 60`.** Время считается от исполнения покупки до подтверждения
   защитного ордера биржей (метки времени журнала обмена).
2. **Биржа — источник истины.** Позиция есть, если на счёте есть остаток актива. Ордер есть, если
   биржа его возвращает.
3. **Каждый ордер идемпотентен.** `newClientOrderId = cb_<epoch8>_<sym>_<bar_ts>_<leg>`, не длиннее
   36 символов. После таймаута ордер сначала ищется по этому id (`GET /api/v3/order?origClientOrderId=`),
   только потом ставится заново.
4. **Решения принимает только политика** (`trading_policy.py` через тот же движок, что у теневой
   книги). Исполнитель ничего не решает, он только исполняет и докладывает.
5. **Подписанные запросы — только на демо-хосты** (`ALLOWED_HOSTS` в `exchange_client.py`);
   `place_order` отказывает, пока `TRADING_ENABLED = False` или `TRADING_MODE != "demo"`.
6. **Каждое действие оставляет след:** запрос — в журнале обмена, решение — в журнале решений со
   списком `client_order_ids`, исполнение — в учёте D. Без этого отчёт D не свяжет сделку с решением.

## 2. Устройство

### 2.1 Процесс `trader/executor.py`

Один долгоживущий процесс, цикл каждые `TRADING_LOOP_SEC = 5` с:

1. дочитать хвост `files/bot_events.jsonl` (тот же `EventTail`, что у теневого портфеля, своё
   смещение в `trader/runtime/executor/`);
2. прогнать события через **внутреннюю бумажную книгу** — копию книги `x4_floor8` E7: тот же
   `decide_entry_explained`, то же стартовое бумажное равенство 10 000, те же слоты. Решения
   книги — это решения исполнителя;
3. исполнить новые решения книги на бирже (§3);
4. на каждом закрытом 15-минутном баре подать позициям `P1Exit.feed` (те же бары `LiveBars`);

**Один экземпляр:** файл блокировки с PID; при старте — проверка, что процесс с этим PID жив и

поэтому из Claude исполнитель не запускается. Приоритет 4, флаги батареи выключены.

Пока исполнитель не работает, позиции защищены аварийными стопами на бирже; трейл не двигается,

### 2.2 Связь с теневой книгой E7

Бумажная книга исполнителя совпадает с книгой `x4_floor8` теневого портфеля по построению
(тот же код, те же события, те же бары). Тест паритета (§7, п. 12) это проверяет. Поэтому каждую
реальную сделку можно поставить рядом с её бумажной двойняшкой. Разница «факт − бумага» по сделке —
это и есть цена исполнения: проскальзывание входа, задержка, выход по аварийному стопу, пыль,
комиссии.

Если реальная позиция закрылась иначе, чем бумажная (сработал аварийный стоп, отказ биржи), книга
**не подстраивается** под факт. Расхождение пишется в журнал решений как `execution_divergence`
с причиной. Так решения остаются сравнимыми с E7, а цена расхождения измеряется.

## 3. Жизнь позиции

```
DECIDED -> ENTRY_SENT -> FILLED -(стоп <= 60 c)-> PROTECTED -> EXIT_SENT -> CLOSED
   |            |           |                       |   \-> STOP_FIRED (аварийный стоп биржи) -> CLOSED
SKIPPED     REJECTED     PARTIAL -> защита на исполненное  \-> cancelReplace стопа при сдвиге трейла
```

### 3.1 Вход

- `POST /api/v3/order` `MARKET BUY` с `quoteOrderQty` = бумажный размер × `TRADING_SCALE`,
  округление вниз до `quoteAssetPrecision`.
- Меньше `max(minNotional × 1.2, TRADING_MIN_ORDER_USDT)` → вход пропускается с кодом
  `below_min_notional` (в журнал решений). Запас ×1.2 нужен, чтобы продажа после падения на 8% и
  удержания комиссии тоже прошла фильтр.
- Отказ фильтра или биржи → `REJECTED`, код и сообщение биржи в журнал, без повтора.
- **Одна реальная позиция на монету.** Остаток на споте общий для монеты, поэтому вторая
  бумажная позиция в той же монете (например, 15m и 1h) на бирже не открывается: код
  `asset_held`. Бумажная книга её ведёт как обычно.
- Комиссия покупки без BNB удерживается в монете: на счёте остаётся `executedQty × 0.999`. Все
  дальнейшие ордера считаются от **свободного остатка** на счёте, округлённого вниз до `stepSize`.

### 3.2 Защита

- Сразу после исполнения, в том же цикле: `POST /api/v3/order` `STOP_LOSS SELL` на свободный
  остаток, `stopPrice = стоп политики × (1 − TRADING_CATASTROPHE_GAP_PCT/100)`, округление по
  `tickSize` вниз.
- Отказ → повтор до 3 раз в пределах 10 с → если защиты всё ещё нет, `MARKET SELL` всего остатка
  и тревога `protection_failed`. Инвариант 1 важнее сделки.
- Политика с TP (в будущем, не X4) ставит вместо стопа OCO: `POST /api/v3/orderList/oco`, верхняя
  нога `LIMIT_MAKER` (TP), нижняя `STOP_LOSS`.

### 3.3 Трейл и выход по правилу политики

- На закрытом баре `P1Exit.feed` поднимает стоп политики. Если новый аварийный уровень выше
  стоящего на ≥ `TRADING_TRAIL_UPDATE_MIN_PCT = 0.2`% — `POST /api/v3/order/cancelReplace`
  (`cancelReplaceMode = STOP_ON_FAILURE`): отмена старого стопа и новый стоп одним запросом.
  Ответ «отмена прошла, новый не встал» → новый стоп отдельным запросом, затем путь §3.2.
- `P1Exit.feed` вернул выход (`trail` — закрытие ниже стопа, или `time` — 96 баров):
  отмена стопа (`DELETE /api/v3/order`) → `MARKET SELL` свободного остатка. Остаток меньше
  `minQty` / `minNotional` — пыль: в капитале учитывается, ордером не продаётся.
- **Почему аварийный стоп ниже, а не на уровне политики.** Результат X4 (H3, E7) получен на правиле
  «закрытие бара ниже стопа». Биржевой стоп на том же уровне срабатывал бы на любой тени свечи —
  это другая политика, её никто не проверял. Аварийный стоп защищает от падения исполнителя и от
  обвала, а обычный выход идёт по правилу. Вариант «стоп на бирже = стоп политики» — отдельная
  гипотеза для E1 (реплей на 1-минутных барах), не часть этой спеки.

### 3.4 Наблюдение за защитой

Раз в 15 с для каждой открытой позиции — `GET /api/v3/order` по её стопу (вес 4; 10 позиций ×
4 раза в минуту = 160 веса из 6000). Стоп `FILLED` → позиция `STOP_FIRED → CLOSED`, бумажная
книга не трогается, пишется `execution_divergence`. Стоп `CANCELED` / `EXPIRED` без нашей команды →
новый стоп по §3.2 и тревога. Поток пользователя по WebSocket заменит опрос на этапе B; до тех
пор опрос — основной способ.

### 3.5 Частичное исполнение

Рыночная покупка может исполниться не полностью (`EXPIRED` с `executedQty > 0`). Защита ставится
на фактический остаток. Бумажная книга продолжает со своим размером; разница пишется.

## 4. Риск-ограничения реальных денег демо-счёта

Ограничения политики (слоты, дневной лимит книги) — в бумажной книге, как у E7. Здесь — поверх
них, на реальные суммы, все в `trader/trader_config.py`:

| параметр | значение | действие |
|---|---|---|
| `TRADING_SCALE` | 0.02 | реальный размер = бумажный × 0.02 (бумажный слот ~1 000 → ~20 USDT) |
| `TRADING_MIN_ORDER_USDT` | 6 | ниже — пропуск входа (`below_min_notional`) |
| `TRADING_MAX_EXPOSURE_USDT` | 250 | сумма открытых позиций по цене входа; выше — пропуск (`exposure_cap`) |
| `TRADING_DAILY_LOSS_LIMIT_USDT` | 25 | реализованный убыток за сутки UTC ≥ 25 → новых входов нет до 00:00 UTC (`daily_loss_limit_real`) |
| `TRADING_KILL_SWITCH_USDT` | 60 | капитал счёта ниже максимума с начала этапа на ≥ 60 USDT → закрыть всё и создать `PAUSE` |
| `TRADING_CATASTROPHE_GAP_PCT` | 3.0 | аварийный стоп на 3% ниже стопа политики |

При 10 позициях по ~20 USDT в рынке не больше ~200 USDT из ~10 000 (2%). Худший сценарий —
все позиции проходят аварийный стоп: 8% пола + 3% зазора = −11% → около −22 USDT. Так что
аварийный выключатель на 60 USDT срабатывает только при сбое учёта или исполнения, а не от рынка.

## 5. Управление и сверка

### 5.1 Команды оператора — файлы в `trader/runtime/control/`

| файл | действие исполнителя |
|---|---|
| `PAUSE` | новых входов нет; открытые позиции живут по своей защите и правилу |
| `FLATTEN` | отменить все стопы и продать все позиции по рынку, затем создать `PAUSE`, удалить `FLATTEN` |
| `RESET_NOTED` | оператор сбросил демо-баланс: метрика D помечает день `RESET` |

Оператор пишет в чат («поставь на паузу», «закрой всё»), Claude создаёт файл. `PAUSE` снимается
удалением файла. Каждое действие по файлу — запись в журнале решений.

### 5.2 Сверка (`trader/reconcile.py`) — при старте и каждые 300 с

Сравниваются: `account` + `openOrders` с биржи, `positions.json` исполнителя, учёт D.

| расхождение | действие |
|---|---|
| остаток монеты (не пыль) без стопа | поставить аварийный стоп от стопа политики; если позиции нет в состоянии — стоп на −11% от текущей цены и тревога `orphan_balance` |
| стоп без позиции | отменить, тревога `orphan_order` |
| позиция в состоянии, на бирже остатка нет | восстановить закрытие по `myTrades`, `CLOSED`, тревога |
| P − L по метрике D > 0.01% | новых входов нет до разбора (`RECONCILE_FAIL`) |

Тревоги пишутся в журнал решений (`kind = alert`) и попадают в утренний отчёт D.
