# CAP-SHADOW — теневая книга замороженного CAP_W4_X50_H24 на живых данных

Дата: 2026-11-04. Решение оператора: «и то и другое: открывай 2026, потом теневая книга». Трейдер (`trader/`), бумага.
Ни ордеров, ни ключей.

## 1. Зачем

Правило CAP_W4_X50_H24 на 2018–2022 «не доказано, но близко» (`capitulation-basket-cap-1104-spec.md`). Окно 2026
открыто один раз, отдельно. Единственный способ получить ответ на данных, которых не видел ни один прогон, — вести
правило вперёд. Вывод теневой книги не зависит от исхода окна 2026.

## 2. Правило (заморожено, как в тесте)

- **Вселенная дня d:** `xsmom.universe` по дневной панели из свечей сканера W1 (`runtime/scan/bars/`, все пары спота).
  Видны только дни < d.
  - Ликвидность: топ-100 по дневному обороту за 30 дней, нужно не меньше 20 дней.
  - Без плечевых токенов и стейблкоинов (`trading_universe.STABLE_BASES`).
  - Возраст пары не меньше 60 дней. Он считается по первому бару в `history_store` (только чтение). Пары, которых там
    нет, считаются молодыми.
- **Сигнал:** `cap.breadth` при W = 16 баров (4 ч), Y = 10%, минимум 50 пар. Событие — доля ≥ 50%. Следующее событие не
  раньше, чем через 1 + 96 баров.
- **Сделка:** `cap.basket`, вход по закрытию бара t + 1, выход через 96 баров (24 ч), издержки
  `fill_model.model("taker", 1)`, делистинг −50%.
- **Книга:** 10 000 USDT, на каждое событие весь капитал, доходы событий складываются сложным процентом.

## 3. Работа

- **Шаг** `cap_shadow.py step` — внутри `run_shadow.cmd`, каждые 5 мин. Флаг `CAP_SHADOW_ENABLED`; откат — False, шаг
  тогда ничего не делает.
  - Обрабатываются только закрытые бары после последнего обработанного. Состояние — `runtime/cap_shadow/state.json`:
    последний бар, время следующего допустимого события, открытые события.
  - Событие записывается, когда закрылся бар t + 1. Доход — когда закрылся бар выхода; он считается по тем же свечам,
    тем же кодом `cap.basket`.
  - **Контроль считается при записи дохода:** 50 случайных 15m-баров из окна сканера, та же корзина и то же удержание;
    их среднее хранится рядом с событием. Сравнение парное, по событиям.
  - Журнал `runtime/cap_shadow/ledger.jsonl` только дописывается: события, доходы, контроль, пропуски покрытия.
- **Старт:** с первого шага, без задним числом посчитанных событий.

## 4. Чтение `CAP-SHADOW` (решение заранее)

- **COLLECTING** — пока закрытых событий меньше 15.
- **При n ≥ 15:**
  - **KEEP** — нижняя граница 95% ДИ среднего дохода события > 0 и нижняя граница парной разницы с контролем > 0;
  - **REJECT** — верхняя граница среднего дохода < 0;
  - иначе **INCONCLUSIVE**, сбор продолжается.
- **Пересмотр 2027-11-04:** если к этой дате n < 15, итог — **TOO_FEW**, с числами; дальше решает оператор.
- **ANOMALY сразу:**
  - доля обработанных баров с ≥ 50 пар ниже 90% за неделю;
  - событие, у корзины которого меньше 50 пар.
- Деньги — только отдельным решением оператора, не раньше KEEP.

## 5. Тесты (до кода, `trader/test_cap_shadow.py`)

1. Шаг обрабатывает только новые закрытые бары; повторный шаг ничего не меняет.
2. Событие и его доход совпадают с `cap.events` и `cap.basket` на тех же свечах.
3. Пропуск между шагами (машина выключена) догоняется по свечам сканера, если они ещё в окне.
4. Флаг False — шаг ничего не пишет.
5. Чтение: COLLECTING / KEEP / REJECT / INCONCLUSIVE / TOO_FEW по правилам §4.
