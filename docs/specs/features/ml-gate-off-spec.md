# Отключить ML-фильтр входа? — проверка на максимальном периоде

- **Slug:** `ml-gate-off`
- **Status:** VALIDATED 2026-09-27 — **не отключать** (отказ по сделке на текущей модели); поведение не меняется.
- **Вопрос оператора:** «насколько улучшилась бы метрика, если отключить ML-модель» (повод: POL 27.09, ml_proba 0.141–0.143 при пороге 0.15).
- **Truth-harness:** TH-01, TH-04, TH-06, TH-08, TH-10, TH-12, TH-13
- **Скрипт:** `files/_backtest_disable_ml_gate.py`; тест `files/test_ml_gate_off.py`
- **Rollback:** не нужен. Maximum period: 2026-04-06 (первый блок `ml_proba_zone`) … 2026-09-27; shadow не применим.

## Метод (как П-3)

ML-модель блокирует в двух местах: `ml_proba_zone` (порог 0.15) и `ml_filter`
(trend в небычий день, 0.35). Оба стоят рано — до `entry_score`, `trend_quality`
и остальных гейтов. «ML выключен»: каждый заблокированный кандидат (монета ×
таймфрейм × бар) идёт дальше и входит с вероятностью p — долей кандидатов,
прошедших ML, которые стали входом: 15m **13.0%**, 1h **15.7%**. За период
заблокировано 8 487 кандидато-баров на 15m и 2 901 на 1h.

## Вывод

- За весь период ML-фильтр **ничего не отбирал**: заблокированные на 15m
  торговались так же, как вошедшие (−0.03% против −0.04%), а стоил он около
  1 п.п. цели. Но это почти целиком старая модель (до 07.09 — метка с обратным
  смыслом).
- С новой моделью (с 08.09, 3 недели) на 15m фильтр **отбирает**: вошедшие
  +0.86% против +0.16% у отсечённых; выключение не проходит порог неухудшения
  (нижняя граница −0.256 п.п.). Выигрыш по цели при этом +1.8 п.п. ожидаемо
  (+6 дней верхняя граница из 68).
- На 1h выключение безопасно, но цели почти не даёт (+0.1 п.п.).

**Решение: не отключать.** Перечитать при ≥ 2 месяцах данных новой модели (вместе
с E-9, не раньше 2026-11-07): если разрыв «прошедшие − отсечённые» на 15m
сохранится — фильтр оставить; если сойдётся к нулю, как у старой модели, —
отключать на 15m по этой же проверке.
