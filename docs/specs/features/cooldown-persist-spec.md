# Cooldown после выхода переживает перезапуск бота

- **Slug:** `cooldown-persist`
- **Status:** SHIPPED 2026-09-28 (исправление, флаг ON)
- **Truth-harness:** TH-05, TH-07, TH-12, TH-13
- **Код:** `files/monitor.py` (`PersistentCooldowns`, `load_cooldowns`), `files/bot.py`
  (восстановление при старте), `files/config.py` (`COOLDOWN_PERSIST_ENABLED`)
- **Тесты:** `files/test_cooldown_persist.py` (8)
- **Rollback:** `COOLDOWN_PERSIST_ENABLED = False` и перезапуск — прежнее
  поведение (cooldown только в памяти); файл `.runtime/cooldowns.json` можно удалить.

## Дефект

`state.cooldowns` ({монета: вход запрещён до, unix ms}) жил только в памяти. Бот
создаёт состояние заново при каждом старте и восстанавливает только позиции,
поэтому любой перезапуск молча снимал все cooldown. Наблюдение: HBAR 2026-09-28 —
в 09:45 UTC оставалось 12 баров cooldown, сразу после перезапуска в 10:09 журнал
опроса показывает его как свободную монету (`evaluated`).

Cooldown сам по себе проверен (`cooldown-reentry-spec.md`: повторный вход внутри
него не даёт преимущества), значит, снимать его перезапуском — расхождение между
поведением бота и его правилами, а не выигрыш.

## Исправление

`PersistentCooldowns` — словарь, который при каждой записи переписывает
`.runtime/cooldowns.json` (записи только на выходах, десятки ключей); `load_cooldowns()`
при старте читает файл и отбрасывает истёкшие. Остальной код читает его как
обычный dict. Поведение без перезапусков не меняется; maximum period и shadow
не нужны — это восстановление задуманной логики, а не новое правило.

## Следствие: база алерта «продолжает движение» (2026-09-28)

Алерт во время cooldown (`ALERT_DURING_COOLDOWN_ENABLED`) сравнивает цену с базой,
взятой на первом опросе cooldown (≈ цена выхода). Пока cooldown не переживал
перезапуск, это не проявлялось; после исправления первый опрос после перезапуска
брал базой текущую цену. QNT: выход 344.48 (+50.7%), после перезапуска база
226.49 → в канал ушло «+7.3% после нашего выхода» при цене 243 (на 30% ниже
выхода). Исправление: `_begin_or_resume_cooldown_ref` хранит базу вместе с концом
cooldown (`cooldown_refs.json: until`); тот же cooldown после перезапуска сохраняет
базу и флаг «уже оповещали», новый cooldown берёт новую базу. Заодно алерт
переведён с HTML (`<b>`) на Markdown — бот шлёт в Markdown, теги были видны.
Базы монет, чей cooldown был в тот момент, восстановлены по фактическим ценам
выхода из `bot_events.jsonl`. Тесты: 3 в `test_cooldown_persist.py`.
