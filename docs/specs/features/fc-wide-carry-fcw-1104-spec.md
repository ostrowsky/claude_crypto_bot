# FC-W — пассивный FC на нескольких самых ликвидных парах: предрегистрация

Дата: 2026-11-04. Решение оператора: «да, начинай с CAP и FC-W, загрузку разрешаю». Офлайн, трейдер (`trader/`).

## 1. Вопрос

FC_PASSIVE — лонг спота BTC и ETH против шорта перпа, L = 1. Он доказан на трёх периодах, но мал (~0.9 %/год на 2026).
Отбор пар по высокому фандингу отвергнут (`fc_funding_carry_selection`): в 7 из 8 вариантов были ликвидации, потому что
высокий фандинг бывает у монет, которые резко растут.

**Вопрос:** даёт ли тот же пассивный FC на N самых ликвидных парах, без отбора по фандингу, больше дохода на тот же
капитал, чем BTC+ETH, и без ликвидаций?

## 2. Правило (заморожено)

- **Пары дня d:**
  - вселенная — `carry.eligible`: топ-100 спота по ликвидности за 30 дней, у пары есть перп и фандинг;
  - цель — первые N пар этого списка;
  - держим пару, пока она в первых 2N (гистерезис против оборота), свободные места заполняются по порядку ликвидности.
- **Кандидаты (3):** `FCW_N4`, `FCW_N6`, `FCW_N10`.
- **Всё остальное — как в FC_PASSIVE (`carry.simulate`):**
  - L = 1, изолированная маржа, стоп маржи 50%;
  - издержки `carry.fees(1)` на обе ноги;
  - капитал 1 000 000 USDT, на пару C / N;
  - живой фандинг; вход и выход по первому 15m-бару дня.

## 4. Допуск на трейне (все условия, α = 0.05 / 3)

1. Средний дневной R: нижняя граница ДИ > 0.
2. Ликвидаций 0.
3. Парная разница с FC_PASSIVE по дням: нижняя граница ДИ > 0. FC-W должен быть лучше BTC+ETH на тот же капитал,
   иначе его незачем вводить.
4. Средний R больше p95 случайного контроля `carry.random_control`: те же N, случайные пары вселенной, 50 сидов.
5. Не меньше 2 из 3 лет со средним R ≥ 0.

- PBO по 3 кандидатам публикуется. С 3 кандидатами PBO мало что значит, поэтому это не критерий.
- **Победитель** — допущенный кандидат с наибольшим средним R.
- **Отложенный период** (α = 0.05): R нижняя граница > 0, ликвидаций 0, парная разница с FC_PASSIVE за тот же период:
  нижняя граница > 0.
- Нет победителя → STOP, запись в `already_tried.jsonl`.

## 5. Тесты (до кода, `trader/test_fcw.py`)

1. Выбор пар: первые N по ликвидности; держим, пока пара в первых 2N; свободные места по порядку.
2. Кандидаты: 3 имени, K = N.
3. Сопоставление перпов архива со спотом: префикс множителя, отказ при расхождении цен.
4. Допуск §4 по каждому условию.

**Почему отвергнут.** Ни один кандидат не лучше BTC+ETH, у всех есть ликвидации, ни один не обходит p95 случайных пар.
Каждая пара сверх BTC и ETH ухудшает результат: R падает, а ликвидации, стопы маржи и просадка растут. Альты на L = 1
дают шорт-сквизы, которые съедают их фандинг. FCW_N10 хуже FC_PASSIVE достоверно.

**Вывод.** Пассивный FC лучше всего на BTC+ETH. Расширять его на альты не нужно. Загруженные данные 2020–2022
(157 перпов, `runtime/experiments/bh_market_wide.npz`) пригодятся для других гипотез.
