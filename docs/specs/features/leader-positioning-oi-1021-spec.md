# Рост открытого интереса у лидера и на пересечении: перепроверка одного зафиксированного правила (2026-10-21)

- **Slug:** `leader-positioning-oi-1021`
- **Статус:** предрегистрация. Поведение бота не меняется: нет флага и нет shadow.
  Результат — только рекомендация.
- **Владелец:** оператор + Claude
- **Readout:** `LEADER-POSITIONING-OI` в `files/readout_registry.json`. Срок
  2026-12-16, окно данных с 2026-10-20.
- **Код:**
  - `files/_readout_leader_positioning_oi.py` — расчёт;
  - `readouts.readout_leader_positioning_oi` — чтение результата;
  - шаг `leader positioning oi` в `pipeline_run.py` перед `readouts`.
- **Тесты:** `files/test_leader_positioning_oi.py`. Написаны до кода.
- **Truth harness:**
  - TH-01 — база рядом с precision;
  - TH-03 — только новые дни, деление по времени;
  - TH-06 — сравнение с собственными входами бота;
  - TH-10 — «рано судить», пока мало данных;
  - TH-12 — правило одно и зафиксировано до данных;
  - TH-13 — правило тождественно `leader_alert.find_leaders` / `_backtest_crossing_entry.py`.

## Почему

Первая проверка позиционирования (`docs/reports/2026-10-18-leader-positioning-readout.md`,
окно 2026-08-21..10-19) нашла всего один признак с одинаковым знаком в обеих половинах.
Это `oi_1h` в момент алерта лидера: AUC 0.617 на train и 0.698 на тесте. Но в тесте было
только 9 продолжений роста, так что вердикт — «рано судить». Вопрос D (вход на пересечении
+2.5 % при rank ≤ 3) тоже остался без ответа: 27 входов при нужных 60.

Если через два месяца снова перебирать сотни правил на тех же данных, получится тот же
подгон, что и в первые четыре захода. Поэтому правило фиксируется сейчас, до появления
данных, на которых его будут судить.

## Правило (заморожено 2026-10-21)

Вход проходит правило, если `oi_1h` последнего снимка позиционирования (не старше 3 ч)
не меньше **медианы** `oi_1h` той же популяции в уже просмотренном окне
2026-08-21..2026-10-19. Медианы считаются по популяции до фильтра:

| популяция | медиана `oi_1h`, % | n в просмотренном окне |
|---|---|---|
| A — алерты лидера с позиционированием | 1.336 (`1.336080`) | 129 алертов, 32 продолжения |
| D — пересечения rank ≤ 3 с позиционированием | 0.112 (`0.111583`) | 328 пересечений, 56 полных дней |

Константы `OI1H_MEDIAN_A` / `OI1H_MEDIAN_D` хранятся в скрипте. Посчитаны командой
`--seen` и после этого не меняются. Судим **только по дням с 2026-10-20**.

## Критерии (до данных)

**A — продолжает ли лидер рост.**
- Популяция: алерты, воспроизведённые через `leader_alert.find_leaders` (первый
  подходящий бар монеты, не больше 3 в день), у которых есть снимок.
- Метка: после алерта до конца UTC-дня есть 15m-close ≥ цена алерта +5 %, и день
  закрывается выше цены алерта.
- Вердикты:
  - `TOO_EARLY` — меньше 30 продолжений во всей популяции;
  - `SUPPORTED` — нижняя граница Wilson 95 % для precision правила выше базы;
  - `REFUTED` — precision правила не выше базы, или правило ничего не отбирает;
  - иначе `INCONCLUSIVE`.
- Для информации: средний pnl отобранных алертов на трейле k = 3, пол 8 %, 7 дней
  (`_backtest_leader_mode_v2.py`), с 95 % bootstrap.

**D — вход на пересечении.**
- Популяция строится как в `_backtest_crossing_entry.py`: rank ≤ 3, первый close ≥ +2.5 %
  от UTC-open, одна запись на монету в день, бот работал весь день. Выход — `sim_exit`.
- Вердикты:
  - `TOO_EARLY` — меньше 60 входов по правилу;
  - `SUPPORTED` — выполнены все три условия из `late-entry-0930-spec.md`:
    1. precision ≥ precision 15m-входов бота в те же дни;
    2. нижняя граница 95 % для pnl ≥ среднее бота − 0.10 pp;
    3. охват ≥ 10 % late/none winner-days. Стадия — как в `_research_late_entry.py`:
       первый вход бота после пересечения или входа нет.
  - иначе `REFUTED`.
- Это **пятый заход** на входы на пересечении, считать его в TH-12.

**Итог.**
- `TOO_EARLY`, пока хотя бы одна часть `TOO_EARLY`.
- `SUPPORTED`, если подтверждена хотя бы одна часть.
- `INCONCLUSIVE`, если хотя бы одна часть `INCONCLUSIVE`.
- Иначе `REFUTED`.

Итоговые вердикты окончательны: `FINAL_STATUSES` в `readouts.py`. `SUPPORTED`
означает «предложить отдельную гипотезу с флагом и shadow». Применять сразу нельзя.

## Как работает

- Шаг `leader positioning oi` в `pipeline_run.py` идёт перед `readouts`, таймаут 1500 с.
  До 2026-12-16 он ничего не делает.
- Начиная со срока, шаг каждое утро пересчитывает окно с 2026-10-20 по вчерашний
  размеченный день. Результат пишется в `.runtime/backtests/leader_positioning_oi.json`.
  Пересчёт идёт, пока вердикт `TOO_EARLY`.
- `readouts.py` только читает этот файл. Тяжёлая 15m-сетка не попадает в 900-секундный
  таймаут шага readouts.

## Когда ждать ответа

При темпе первого окна это около 0.5 продолжения в день для A и около 3 входов в день по
правилу для D. Значит, 30 продолжений и 60 входов набираются к сроку 2026-12-16. Если нет,
readout пишет `TOO_EARLY` и перечитывается ежедневно.

Важно: если запись позиционирования прервётся, данных не станет больше. Запись делает
`positioning_recorder.py` раз в 2 ч; в сентябре был пропуск 51 ч.
