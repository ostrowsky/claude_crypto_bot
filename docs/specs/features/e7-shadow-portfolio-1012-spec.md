# E7 — теневые портфели: широкий трейл (X4) против выходов бота на живых данных

Статус: **спека**, кода нет. Дата 2026-10-12. Родители: `autonomous-trading-roadmap-1010-spec.md`
(этап E, шаг E7), `h3-exits-money-1011-spec.md` (X4 improves = да, profitable = нет),
`execution-replay-e1-1010-spec.md` (§2 контракт одной функции решения),
`daily-revenue-metric-1010-spec.md`. Приложение: `trader/`, бота не меняет. Порядок: спека → тесты
→ код. Правила truth harness: TH-03, TH-04, TH-05, TH-07, TH-10, TH-13.

## 1. Зачем

X4 прошёл предзаявленный критерий на июле–октябре, но эта половина не свежая (H3 §5). Чистое
подтверждение даёт только будущее. Теневой портфель — бумажная торговля в реальном времени с
независимым состоянием (shadow twin, §6.2 целевой спеки). Она отвечает на два вопроса:
1. держится ли на новых днях эффект X4 против выходов бота (парная разница дневной выручки);
2. становится ли X4 прибыльным.

Деньги и ордера не участвуют. Демо-счёт не трогается.

## 2. Портфели (у каждого своё состояние)

| имя | входы | выходы | слоты |
|---|---|---|---|
| **P0** `champion` | все новые входы бота (`entry` в `files/bot_events.jsonl`) | реальный выход бота (`exit` того же sym/tf, цена из события) | 10 равных от своего капитала |
| **P4** `x4_floor8` | те же входы | P-1 трейл от бара входа с буфером ≥ 8% для всех режимов, горизонт 96 баров; 1h-сделки судятся на часовых закрытиях | 10 равных от своего капитала |

- Стартовый капитал каждого портфеля — 10 000 USDT (бумажный). Издержки уровня 1
  (`fill_model.model("taker", 1)`).
- Решения принимают `trading_policy.decide_entry` и **пошаговая** версия `exit_plan` — та же
  логика, что в реплее (контракт E1 §2).
- Вход — по цене из события бота. Выход P0 — по цене выхода бота. Выход P4 — по закрытию бара
  пробоя. Как в реплее.

## 3. Данные (только чтение)

- **События бота:** хвост `files/bot_events.jsonl`. Трейдер помнит смещение в байтах и обрабатывает
  только новые строки `entry` и `exit`. Если файл стал короче смещения (ротация), чтение идёт с
  начала с дедупликацией по (sym, tf, ts, event).
- **Свечи 15m по символам с открытой позицией P4:** публичный `GET /api/v3/klines` на
  `api.binance.com`, без ключа, последние 500 баров (ATR по Уайлдеру сходится). Учитываются только
  закрытые бары. Запросы идут через `exchange_client` с общим сроком на запрос.
- **Расхождение ATR живой ленты и сетки реплея** пишется в журнал (диагностика, §7). Цель — не
  больше 1% от ATR в медиане.

## 4. Процесс

- `trader/shadow_portfolio.py step` — один шаг:
  1. прочитать новые события;
  2. обработать их по времени;
  3. для открытых позиций P4 подтянуть закрытые бары и пройти выход бар за баром;
  4. записать капитал обоих портфелей на 00:00 UTC (и снимок каждого шага).
- Расписание: та же задача, что у рекордера, или своя, каждые 5 минут. Сторож процесса 120 с.
- **Состояние:** `trader/runtime/shadow/state.json` (атомарная запись через `.tmp` + `replace`).
  Хранит позиции, кэш, смещение, кулдауны и капитал на начало дня.
- **Журнал:** `trader/runtime/shadow/ledger.jsonl`, только дозапись: вход, выход, причина, цены,
  издержки, капитал.
- **Пропуск шага** (компьютер выключен, сбой): следующий шаг догоняет. События читаются с
  сохранённого смещения, бары P4 — с последнего обработанного. Решения не теряются, но день
  может получить статус `BOT_DOWN` по метрике (TH-05), если сам бот не работал.

## 5. Паритет с реплеем (тест до кода)

На исторических событиях и сетке реплея шаговый движок, получающий бары из сетки, даёт **те же
сделки** (вход, бар выхода, цена выхода, причина), что `execution_replay.run` для P0 и для X4.
Допуск — 1e-9 по цене. Без паритета теневой портфель меряет не то, что реплей, и расхождение
нельзя будет объяснить.

## 6. Разбор (предзаявлен, `files`-реестр бота не трогается — свой реестр трейдера)

`trader/runtime/shadow/READOUT_E7.json`, считает `trader/shadow_readout.py`:
- **окно:** с первого полного UTC-дня после запуска; минимум **28** дней со статусом `FULL` или
  `BOT_DOWN` и ≥ **150** закрытых сделок P4; срок — запуск + 28 дней;
- **`KEEP_X4`:** нижняя граница 95% парной разницы дневной выручки (P4 − P0), блочный бутстрэп
  5 дней, > 0;
- **`X4_PROFITABLE`:**
  - средняя дневная R P4 > 0;
  - нижняя граница 95% чистого результата сделки P4 > 0;
  - вместе с `KEEP_X4` это единственное основание для спеки демо-торговли (этап C) с X4;
- **`REJECT_X4`:** верхняя граница 95% парной разницы < 0;
- **иначе `INCONCLUSIVE`:** окно продлевается ещё на 28 дней. Критерии **не ослабляются**.
- **Всегда печатается:**
  - n дней и сделок;
  - средние R обоих портфелей с ДИ;
  - бенчмарк BTC за те же дни;
  - разрыв «реплей тех же дней ↔ тень» (после ночного бэкфилла истории реплей пересчитывает
    те же дни);
  - расхождение ATR.

## 7. Требования к коду (тесты до кода)

1. **Паритет** (§5) для P0 и P4 на синтетической сетке с событиями, включая сделку 1h, кулдаун
   не применяется (входы бота), занятые слоты.
2. **Пошаговый выход P4:** для одной позиции выход бар за баром совпадает с `exit_plan(p1_trail,
   floor_override=0.08)` при любом разбиении баров на порции (1, 3, 7 баров за шаг).
3. **Хвост событий:**
   - повторный шаг без новых строк ничего не меняет;
   - частично дописанная последняя строка не читается до перевода строки;
   - при укорочении файла дубли не создаются.
4. **Сопоставление выхода P0:** выход бота сопоставляется с открытой позицией P0 того же (sym, tf);
   выход без позиции игнорируется и пишется в журнал как `orphan_exit`.
5. **Состояние:** запись атомарна, повреждённый `state.json` не перезаписывает журнал. Шаг
   останавливается с ошибкой, а не начинает с нуля молча.
6. **Капитал на 00:00 UTC:** записывается ровно один раз за сутки на портфель, переоценка по
   последнему закрытому бару ≤ 00:00.
7. **Только закрытые бары:** бар, чьё время закрытия позже момента шага, не используется.
8. **Разбор:** `INCONCLUSIVE` при < 28 днях; `KEEP_X4`, `REJECT_X4`, `X4_PROFITABLE` — на
   синтетических рядах с известным ответом.
9. **Границы приложения:**
   - запись только в `trader/runtime/`;
   - `bot_events.jsonl` открывается только на чтение;
   - ни одного подписанного запроса (ключ не нужен).

## 8. Откат

Процесс только читает и пишет в `trader/runtime/shadow/`. Откат: снять задачу планировщика, флаг
`SHADOW_PORTFOLIO_ENABLED = False` в `trader/trader_config.py`.
