# FC-DEMO — исполнение FC_PASSIVE на демо-счёте (спот BTC+ETH в лонг + перп USDⓈ-M в шорт)

Дата: 2026-10-30. Решение оператора 2026-10-29: «все». Это ответ на пункт «перевести демо-капитал на FC_PASSIVE»
после EX-RL1, вместе с паузой X4 (`demo-execution-c-1013-spec.md`, журнал 10-29). Трейдер (`trader/`); бот не
затрагивается.

## 0. Отступление от заранее заданного порядка (раскрыто)

`fc-passive-next-1022-spec.md` (§0, §A.5, §E) требует: исполнение кэрри на демо — отдельная спека, только после
вердикта `KEEP` теневой книги FC-SHADOW и `GO` F0. F0 = GO с 2026-10-22. FC-SHADOW даст вердикт не раньше
2027-01-21. Оператор решил не ждать. Это его решение, оно записано здесь и в журнале родительской спеки. Чего оно не
меняет:
- **Вердикт по доходности FC** по-прежнему даёт только FC-SHADOW на живом фандинге.
- **Демо-деньги — проверка механики, а не дохода.** Фандинг демо считается по демо-книге (F0, 2026-10-21:
  ETH 0.0000206 на демо против 0.0000650 на живом рынке), поэтому кэрри на демо — не живое кэрри. Отчёт обязан
  писать это рядом с любой суммой.

## 1. Что делает

Повторяет `carry.simulate` с `passive_chooser`, L = 1, на демо-счёте с малым капиталом:
- **Пары** BTCUSDT и ETHUSDT. Номинал на пару N = `FC_DEMO_NOTIONAL_USDT` (2 500 — как `LOT_NOTIONAL_USDT` теневой
  книги).
- **Вход** (нет позиции по паре и сегодня по ней не было стопа):
  1. спот `MARKET BUY quoteOrderQty = N` на demo-api, исполнено q;
  2. перп `MARKET SELL quantity = q`, округлённое вниз до шага перпа, на demo-fapi. Изолированная маржа, плечо 1.

  Остаток спота меньше шага перпа — пыль, записывается.
- **Удержание.** Позиция держится, фандинг идёт сам.
- **Маржинальный стоп.** Если эквити шорта (маржа + q × (вход − mark)) < 50% маржи → закрыть обе ноги: перп
  `MARKET BUY reduceOnly`, затем спот `MARKET SELL`. Повторный вход — на следующий UTC-день.

  Расхождение с бэктестом, раскрыто: бэктест проверяет стоп раз в сутки на 00:00, исполнитель — каждый цикл. Это
  строже и безопаснее, но может закрыть позицию, которую бэктест держал бы.
- **Целостность хеджа.** Если вторая нога не исполнилась (отказ, ошибка), первая немедленно откатывается: продать
  спот или откупить перп. Пишется тревога, создаётся `PAUSE` FC.
- **Отметки.** Раз в сутки записываются: стоимость спота, нереализованный результат перпа, маржа, фандинг за сутки
  (`/fapi/v1/income FUNDING_FEE`), комиссии, дельта хеджа |q_спот − q_перп|.

## 2. Безопасность и управление

- `FC_DEMO_ENABLED` (по умолчанию False) — без него шаг ничего не делает. `FC_DEMO_MODE`:
  - `"paper"` — сделки моделируются по живым ценам, ордеров нет;
  - `"demo"` — реальные ордера только на demo-api и demo-fapi. Подпись разрешена только на `demo-*`
    (`exchange_client.ALLOWED_HOSTS`).
- Ордера идут через `_trading_allowed()` клиента: они разрешены, только если `TRADING_ENABLED`, `TRADING_MODE = "demo"`
  и хост `demo-*`.
- **Управление файлами** в `trader/runtime/fc_demo/control/`:
  - `PAUSE` — новых входов нет;
  - `FLATTEN` — закрыть обе ноги по обеим парам и создать `PAUSE`.
- **Аварийный выключатель.** Если суммарная эквити FC ниже начальной на `FC_DEMO_KILL_USDT` (300), выполняется
  `FLATTEN`.
- **Журнал решений.** `fc_entry`, `fc_exit`, `fc_mark`, `fc_alert` пишутся в `runtime/audit/decisions`, с
  clientOrderId обеих ног.
- **Откат:** `FC_DEMO_ENABLED = False` и `FLATTEN`.

## 3. Где работает

Шаг `fc_demo.py step` добавляется в `run_shadow.cmd` после `fc_shadow` (задача `CryptoBot_TraderShadow`, каждые
5 мин). Новой задачи планировщика нет. Вход и отметка — один раз в UTC-день, после закрытия первого 15m-бара
(≥ 00:15 UTC). Проверка стопа — каждый цикл.

## 4. Чтение результата (механика, без вердикта о доходе)

Чтение `FC-DEMO-MECH`, не раньше 14 дней работы:
- **хедж:** дельта ≤ шага перпа каждый день;
- **фандинг:** начисленный за день против q × mark × ставка демо `premiumIndex` (расхождение ≤ 5%);
- **комиссии:** фактические против модели (перп 0.05% / спот 0.10%);
- **стопы:** 0 непредвиденных; тревог «одна нога» — 0.

Доходность сравнивается только с FC-SHADOW и только как справка.

## 5. Тесты (до кода, `trader/test_fc_demo.py`)

1. **Выключено.** `FC_DEMO_ENABLED = False` → шаг ничего не делает.
2. **Вход** (paper и поддельная биржа):
   - спот покупает на N, перп продаёт q, округлённое вниз до шага;
   - пыль записывается;
   - журнал содержит `fc_entry` с clientOrderId обеих ног;
   - вход один раз в день, не раньше 00:15 UTC.
3. **Откат одной ноги.** Перп отклонён → спот продан, `fc_alert one_leg`, создан `PAUSE`, позиции нет.
4. **Маржинальный стоп.** Mark выше входа на 51% → обе ноги закрыты (сначала перп reduceOnly), повторный вход не
   раньше следующего дня.
5. **Управление:** `PAUSE` → входов нет, позиции держатся; `FLATTEN` → обе ноги закрыты, создан `PAUSE`.
6. **Аварийный выключатель.** Эквити ниже начальной на 300 → `FLATTEN`.
7. **Отметка дня:** стоимость спота, результат перпа, маржа, фандинг, дельта хеджа.
8. **Хосты.** Новые методы `fut_order` и `fut_positions` подписывают запросы только на demo-fapi; `fut_order` идёт
   через `_trading_allowed`.
