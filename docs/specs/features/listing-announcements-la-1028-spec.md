# LA — объявления бирж как источник информации до движения цены (спецификация сбора данных и проверки)

Дата: 2026-10-28. Решение оператора 2026-10-28: начать с этой гипотезы — единственного непроверенного источника
информации, который появляется раньше движения цены. Приложение `trader/`, сигнальный бот не меняется.
Порядок: спека → тесты → код. Правила truth harness: TH-02, TH-03, TH-05, TH-07, TH-10, TH-12, TH-13.

## 0. Зачем

Двенадцать проверок на цене, объёме, фандинге, позиционировании и сезонности не нашли входа с положительным
ожиданием. Все они смотрят на сам рынок, который узнаёт о новости тогда же, когда начинается движение.

Объявление биржи — событие с точным временем публикации. Часть сильных однодневных ростов, похоже, начинается с
объявлений: листинг на другой бирже, новый фьючерс, добавление в маржу и т. п. Проверено это ни разу не было.

## 1. Источники (проверено 2026-10-28, только чтение, публичные API без ключей)

| источник | что | глубина истории | статус |
|---|---|---|---|
| Binance CMS, раздел 48 «New Cryptocurrency Listing» | спот-листинги, новые бессрочные фьючерсы, bStocks | 2 290 статей; стр. 50 из ~115 — 2023-11 | отвечает |
| OKX `/api/v5/support/announcements`, `announcements-new-listings` | листинги OKX | 53 страницы, до 2023-03 | отвечает |
| Bybit `/v5/announcements/index`, `new_crypto` | листинги Bybit | 1 820 записей | отвечает |
| Upbit `api-manager.upbit.com` | KRW-листинги | не проверено | встроенный Python не прошёл проверку SSL-сертификата |

Разделы о делистинге и «теге мониторинга» Binance — отдельные разделы CMS. Их номера проверяются при сборе.

Upbit подключается, только если удастся проверить сертификат штатно, через пакет сертификатов. Проверку SSL
не отключаю.

## 2. Сбор (этап LA-1)

**Хранилище** — `trader/runtime/announcements/<source>.jsonl`, только дозапись, идемпотентно по `(source, id)`.

**Запись** содержит:
- `id`, `source`, `catalog`, `title`, `url`;
- `t_pub` — время публикации из источника, мс UTC;
- `t_seen` — когда мы её получили;
- `raw` — исходный объект без изменений.

**Однократная выгрузка истории.** Все страницы трёх источников с 2023-01-01 — около 120 + 53 + 92 запроса, с паузой
≥ 1 с между запросами.

**Живой сбор.** Каждые 5 минут — первая страница каждого источника. Новые записи получают `t_seen`. Задержка
`t_seen − t_pub` измеряется: это верхняя граница того, как быстро мы могли бы действовать вживую.

**Хосты** добавляются в `exchange_client.PUBLIC_HOSTS` как публичные хосты только для чтения: `www.binance.com`,
`www.okx.com`, `api.bybit.com`. Подписанные запросы на них запрещены, это проверяет тест.

## 3. Разметка событий (этап LA-2)

**Тикеры.** Тикер или тикеры берутся из заголовка детерминированным правилом: в скобках, например `(ABC)`, или в виде
`ABCUSDT`. Затем тикер сопоставляется со спот-парами Binance к USDT, включая делистинговые: `history_store` и
exchangeInfo.

**Типы событий:**
- `BN_SPOT_NEW` — Binance открывает спот новой монеты. На Binance до листинга монету купить нельзя, поэтому для покупки
  на споте это событие **не годится**. Пишется только для справки и для отложенной N6.
- `BN_PERP_NEW` — Binance Futures запускает бессрочный контракт на монету, **уже торгуемую** на споте Binance.
- `OKX_SPOT_NEW`, `BYBIT_SPOT_NEW` — другая биржа добавляет монету, уже торгуемую на споте Binance.
- `BN_MARGIN`, `BN_OTHER` — прочее: маржа, earn, convert. Только для справки.
- `BN_DELIST`, `BN_MONITOR` — отрицательные события. В длинной стратегии они фильтр или выход, а не вход.

**Пригодно для торговли** только событие, у которого монета торговалась на споте Binance в момент `t_pub`: есть
15m-бар до `t_pub` в истории.

**Ручная сверка разметки.** 50 случайных событий трейна (seed фиксирован) проверяются глазами: тикер, тип и время.
Доля ошибок записывается сюда. При > 10% ошибок правило разметки исправляется **до** любого расчёта доходности.

## 4. Проверка (этап LA-3)

**Вход.** Покупка по закрытию первого 15m-бара, который начинается не раньше `t_pub + 1 мин`. Минута — запас на
задержку. Вживую задержка будет измерена в LA-1, и если она больше, вход сдвигается на измеренную p90.

**Сетка, заранее (9 × число типов):**
- выход — по времени H ∈ {1 ч, 4 ч, 24 ч} либо P-1 трейл X4 (пол 8%, 96 баров);
- плюс вариант с фильтром «не входить, если с открытия суток уже +10%».

**Деньги.** `execution_replay` / `fill_model` уровень 1: тейкер 0.10% + 8 б.п. Книга — 10 слотов.

**Окна.** Трейн — события 2023-03-01 .. 2025-12-31. Тест 2026 открывается один раз и только по решению оператора.

**Контроли:**
1. та же монета, случайный момент того же месяца без событий;
2. тот же момент, случайная монета из топ-100 по ликвидности.

Оба по 50 сидов. Сравнение с EW рынка за то же окно.

**Проверка на утечку (TH-02).**
- Доходность монеты за 4 ч и за 24 ч **до** `t_pub`. Если рост до объявления сопоставим с ростом после, объявление
  не опережает рынок: о нём узнают раньше. Тогда это не сигнал для нас.
- Отдельно публикуется доля событий, где рост +2.5% случился до `t_pub`.

**Допуск на трейне** — все условия:
1. mean R > p95 обоих контролей;
2. нижняя граница ДИ R > 0;
3. сделок ≥ 100;
4. ≥ 2 из 3 лет ≥ 0;
5. PBO < 0.5 по сетке типа.

Победитель по типу; тест с поправкой α = 0.05 / k.

## 5. Тесты (до кода)

1. Хранилище:
   - идемпотентность по `(source, id)`;
   - `t_pub` берётся из источника, `t_seen` — время записи;
   - пагинация до заданной даты.
2. Парсинг тикеров:
   - скобки, `XXXUSDT`, несколько тикеров в заголовке;
   - отказ на заголовке без тикера;
   - сопоставление со спот-парами, включая переименования из `history_store`.
3. Типы событий — по набору реальных заголовков, сохранённых как фикстуры: 10 на каждый тип.
4. Пригодность для торговли: монета без 15m-бара до `t_pub` не входит.
5. Время входа: первый бар, начинающийся ≥ `t_pub + задержка`. Бар, на котором вышло объявление, не используется.
6. Утечка: доходность до `t_pub` считается только по барам с закрытием ≤ `t_pub`.
7. Контроли: монета и момент выбираются без событий, и выбор воспроизводим по seed.
8. Изоляция: нет подписанных запросов, новые хосты только публичные, файлы бота не пишутся.
