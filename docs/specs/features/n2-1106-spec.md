# N2: котировка на USDC-перпе с хеджем на USDT-перпе

Раздел дизайна: `n-family-experiment-designs-1105-spec.md` §4 (86dc8c9). Зависит от N1-A и N1-C (`n1-1106-spec.md`). Коммитится до загрузки ленты и до расчётов.

Инварианты: TH-03, TH-04, TH-05, TH-08, TH-10, TH-11, TH-12. Семейство N2, α = 0.05, 2 кандидата по 0.025. Живого исполнения нет.

## 1. Что фиксируется до данных

**Пары.** (BTCUSDC, BTCUSDT), (ETHUSDC, ETHUSDT), третья — самый ликвидный USDC-перп ранга ≤ 20 из допущенных по N1-C, кроме BTC и ETH. По N1-C это `SOLUSDC`, медиана 735 млн USDC в день; ранг USDT-версии проверяется по `n_common.Volumes` на 2026-01-01 перед загрузкой третьей пары, и если ранг > 20, берётся следующая допущенная монета. Группа издержек: BTC, ETH = B1, третья = B2.

**Инвентарь (листинг 2026-11-06).**

| Символ | Пилот, 3 дня, МБ | Разведка, 22 дня, МБ |
|---|---|---|
| BTCUSDC | 20.9 | 109.5 |
| BTCUSDT | 82.7 | 386.6 |
| ETHUSDC | 42.0 | 205.9 |
| ETHUSDT | 117.2 | 538.1 |
| SOLUSDC | 9.8 | 45.2 |

Пилот и разведка меньше 2 ГБ и идут без разрешения. **Решающее окно вперёд (30 дней, ~67 МБ в день, ~2 ГБ сверху) поднимает эксперимент выше 2 ГБ: его загрузка только с разрешения оператора.** Лента хранится в `runtime/tape_n2/`.

**Задержка котировки считается один раз.** Дизайн задаёт её дважды: F(t) берётся по ленте ≤ t − L_q (п. 1), и новая цена действует через L_q после решения (п. 3). В сопроводительной записке оператор указал, что двойной счёт исправлен, а текст остался с обоими пунктами. Читается это как одна задержка: решение принимается в момент d по ленте ≤ d и начинает действовать в e = d + L_q. На рынке в момент t = e стоит цена по ленте ≤ t − L_q. Оба пункта выполнены, задержка одна. Тест дизайна «F(t) не использует сделки позже t − L_q» остаётся. Чтение вынесено оператору в отчёте.

**Расписание решений.** Первое — на первой сделке USDT-перпа окна. Следующее — первая сделка не раньше d + 200 мс, где отклонение от F решения > 0.5 б.п., но не позже d + 1 000 мс: на границе 1 с обновление происходит по последней цене. Минимальный шаг 200 мс — это лимит 5 изменений в секунду на сторону. Обе стороны меняются вместе.

**После исполнения.** Сторона снята. Решение о выставлении в τ, действует в R = max(τ + L_q, последнее изменение стороны + 200 мс), цена по ленте ≤ R − L_q. Плановые обновления этой стороны игнорируются, пока не пройдёт 200 мс от R.

**Объём.** q = min(1 000 USD, номинал сделки, остаток до предела G). Частичное исполнение тоже снимает сторону.

**Предел запаса.** Номинал по цене исполнения на ногу, G = 20 000 USD. Сторона, увеличивающая позицию, при достижении предела снимается. Когда встречное исполнение возвращает позицию ниже предела, она выставляется по правилу выше.

**Хедж.** Первая сделка USDT-перпа с меткой ≥ τ + L_h, плюс проскальзывание и тейкер 0.050%. Хедж считается открытым сразу, задержка влияет только на цену.

**Курс.** Закрытие последней минуты USDCUSDT, закрытой не позже момента потока (`t + 60 000 ≤ τ`). Заглядывания нет.

**Учёт.** Два кошелька: USDC и USDT.
- Итог = W_usdc · fx_конец + W_usdt.
- Каждый поток USDC учитывается по fx его момента. Разность с оценкой по fx_конец — это вклад курса.
- Тождество: итог = спред − комиссии − проскальзывание + фандинг + курс + закрытие остатка. На нём стоит тест.
- Спред исполнения = s · qty · (H − x · fx_τ), где H — цена хеджа без проскальзывания.

**Фандинг.** На моментах начислений обеих версий на текущую позицию, по последней цене этой версии. Перед `2025-12-31` данные уже есть в `runtime/usdc/`.

**Переоценка.** В 00:00 UTC: E = (W_usdc + Q·P_usdc) · fx + W_usdt − Q·P_usdt. Дневной доход = разность E. В конце окна закрытие остатка тейкером по обеим ногам: USDC-M 0.040%, USDT-M 0.050%, плюс проскальзывание.

**Главный показатель.** На пару и на пул трёх пар: Σ дневной доход / Σ номинал исполнений, б.п., L = 1 000/1 000. Каждая пара считается как отдельная книга со своим пределом G, пул — сумма книг.
Бутстрап по дням с блоком 1, отношение сумм, `n_common.ratio_ci`, уровень 97.5%, B = 20 000.

**Кластеры по минуте** нужны для мощности: σ чистого дохода исполнения без фандинга и курса, m — среднее исполнений в занятую минуту, ρ — внутриклассовая корреляция по минутам (однофакторный ANOVA). δ = 1 б.п., α = 0.025.

**Пилот:** считается пул при всех 8 конфигурациях. СТОП без решающего окна, если средний доход ≤ 0 при L = 250/250 и θ = 3 б.п.

**Захваченный спред для критерия «отклонена»:** s · (F_τ − x · fx_τ) / F_τ, где F_τ — последняя сделка USDT-перпа ≤ τ. Маркаут: s · (F_{τ+Δ} − F_τ) / F_τ. Съедает больше 100%, если среднее −маркаут(1 с) ≥ среднего захваченного.

**tickSize** — текущий из `N1_INVENTORY.json`. Исторические значения в архиве недоступны, это записывается в `not_modelled`.

**Не моделируется:** очередь в стакане (исполнение только при сделке строго сквозь цену — прокси), влияние собственной заявки, частичное исполнение хеджа, простой биржи, отказ post-only, лимит изменений на весь счёт.

## 2. Тесты до кода
`trader/test_n2_quote.py` — по списку дизайна:
- исполнение только сделкой строго сквозь цену и с верным `is_buyer_maker`;
- F не использует сделки позже t − L_q; хедж — первая сделка не раньше t + L_h;
- округление до tickSize в неблагоприятную сторону;
- лимит изменений котировки;
- на пределе запаса увеличивающая котировка не выставляется;
- сохранение денег;
- парсер: единицы времени, дубли, сортировка;
- курс без заглядывания, фандинг и его знак, переоценка в конце равна итогу.
