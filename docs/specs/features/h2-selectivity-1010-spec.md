# H2 — меньше сделок: отбор кандидатов по оценке бота (E1, первое семейство)

Статус: **спека**, кода нет. Дата 2026-10-10. Родитель: `execution-replay-e1-1010-spec.md` (§7
протокол, §8 строка H2). Приложение: `trader/` (бота не меняет). Порядок работы: спека → тесты
→ код (правило оператора 2026-10-10). Правила truth harness: TH-01, TH-03, TH-06, TH-08, TH-10, TH-11.

## 1. Вопрос

Чемпион делает около 25 сделок в день. На одних комиссиях это −0.57%/день, а брутто сделки уже
отрицательно (−0.03 / −0.14% на обучении / проверке). Даёт ли **отбор меньшего числа сделок по
оценке, которую бот уже считает** (`ml_proba`, `candidate_score`, `ranker_final_score`),
дневную выручку лучше, чем у той же политики выхода на всех входах бота?

Бюджет алертов уже опровергнут **по раннему входу** (10-01). По деньгам этот вопрос не
проверялся. Это не повтор проверки.

## 2. Данные (из реплея E1, только чтение)

- **Кандидаты:** события `entry` (5 757) и `blocked` (62 106 после дедупликации по монете и бару
  15m, последнее событие бара) из `files/bot_events.jsonl` с 2026-03-01. Оценки берутся из
  события, они записаны в момент решения:

  | оценка | входов с оценкой | blocked с оценкой |
  |---|---|---|
  | `ml_proba` | 4 035 | 42 291 |
  | `candidate_score` | 3 831 | 42 558 |
  | `ranker_final_score` | 3 831 | 27 344 |

  Кандидат без нужной оценки не допускается.
- **Пулы:** `real_entries` (только входы бота) и `all_candidates` (входы + blocked).
- **Сетка:** 15m сигнального watchlist (`exit_validator.Grid` + L/V трейдера). Кандидат вне
  сетки не участвует.

## 3. Политики (зафиксированы до запуска)

- **Выход у всех политик семейства один:** P-1 трейл (`exits.kind = "p1_trail"`, `trail_k`
  кандидата или 2.0, буфер режима из конфига бота). У blocked-кандидатов нет реального выхода,
  поэтому сравниваются только решения о входе.
- **База для парного сравнения:** `p1_trail` на `real_entries` без порога — ровно то, что было в
  E1 §12, тот же выход.
- **Сетка кандидатов:**
  - пул ∈ {real_entries, all_candidates};
  - оценка ∈ {ml_proba, candidate_score, ranker_final_score};
  - порог = квантиль оценки q ∈ {0.50, 0.75, 0.90}, посчитанный **только по кандидатам этого
    пула на обучающей части**;
  - `max_per_day` ∈ {нет, 3, 10} — первые N допущенных за UTC-сутки в реальном порядке, без
    заглядывания вперёд.

  Всего 2 × 3 × 3 × 3 = **54** кандидата.
- **Правила портфеля для `all_candidates`:**
  - не больше одной позиции на монету (`one_per_symbol`);
  - кулдаун после выхода = `COOLDOWN_BARS` из конфига бота (19 баров 15m).

  Для `real_entries` действует то, что уже отражено в решениях бота (кулдауны бота), плюс
  `one_per_symbol`.
- **Слоты и размер:** как у чемпиона — 10 равных слотов от текущего капитала.
- **Издержки:** taker 0.10% на сторону + 8 б.п. на сторону (уровень 1, `fill_model`). Уровни 0 и
  20 б.п. печатаются для победителя справочно.

## 4. Процедура

1. **Обучение** (дни < 2026-07-01): прогнать все 54 кандидата и базу. Для каждого — парная
   разница дневной выручки с базой (среднее, блочный бутстрэп по 5 дней), число сделок, средняя
   R, просадка.
2. **Допуск на обучении:**
   - ≥ 100 сделок;
   - нижняя граница 95% парной разницы > 0.

   Если не прошёл ни один — **СТОП**, проверочная половина не открывается, результат
   отрицательный.
3. **Выбор:** среди допущенных — наибольшая средняя парная разница на обучении. Ровно **один**
   победитель.
4. **Проверка** (дни ≥ 2026-07-01) открывается **один раз**, только для победителя и базы. k = 1
   (одна открытая гипотеза), поправка Бонферрони не расширяет интервал. Запись в
   `trader/runtime/experiments/trials.jsonl`: семейство H2, параметры, epoch, хэши входов.

## 5. Вердикты (как в E1 §7)

- **`improves`** — все условия на проверке:
  - нижняя граница 95% парной разницы с базой > 0;
  - макс. просадка не хуже базы более чем на 5 п.п.;
  - ≥ 60% месяцев с разницей ≥ 0;
  - ≥ 200 сделок.
- **`profitable`:**
  - средняя дневная R победителя > 0;
  - нижняя граница 95% чистого результата сделки > 0;
  - при уровне проскальзывания 1.
- Иначе по каждому: **нет**. «Рано судить» — если интервал парной разницы содержит 0.
- Справочно рядом: парная разница с чемпионом (реальные выходы бота) и с «кэшем».

## 6. Чего H2 не делает

Не меняет бота и не включает торговлю. Принятый `improves` — кандидат в теневой портфель (E7), не
в демо-торговлю. `profitable = нет` означает, что даже лучший отбор теряет деньги, и чемпионом
остаётся «не торговать».

## 7. Требования к коду (проверяются тестами до кода)

1. `Risk.one_per_symbol`: второй кандидат по монете с открытой позицией не допускается. По
   умолчанию False — у чемпиона ничего не меняется (V1–V3).
2. Кулдаун `Risk.cooldown_bars` действует от бара выхода по той же монете.
3. Квантиль-порог считается только по строкам обучающей части выбранного пула; строки проверки
   на него не влияют.
4. `max_per_day` считает допущенных в хронологическом порядке, сброс в 00:00 UTC.
5. Выбор победителя использует только результаты обучения; функция выбора не получает
   результатов проверки.
6. `DailyRevenue.aggregate(alpha=…)` даёт интервал уровня 1 − alpha; при alpha = 0.05/k он
   шире, чем при 0.05.
7. `money_validator`:
   - вердикты `improves` и `profitable` по §5 на синтетике (граничные случаи);
   - бутстрэп чистого результата сделки;
   - запись в журнал попыток только дозаписью.
8. Ни один модуль H2 не пишет вне `trader/runtime/` и не импортирует бота иначе как через
   `trader_config.bot_readonly()`.

## 8. Справочный контроль: случайный отбор (добавлен ПОСЛЕ основного результата, на вердикт не влияет)

**Зачем.** База теряет деньги, поэтому парное сравнение с ней награждает любое сокращение торговли.
Обгоняет ли оценка бота **случайный отбор той же интенсивности**?

**Как.** Тот же пул, что у победителя. Каждый кандидат допускается, если
`hash(seed, sym, ts) < frac`. `frac` равна доле кандидатов пула, прошедших порог победителя на
обучении. Тот же `max_per_day`, тот же выход, те же правила портфеля. 20 зёрен (0..19).

Сравниваются:
- дневная R и чистый результат сделки победителя на проверке;
- распределение того же по 20 случайным контролям;
- перцентиль победителя.

Это описание, а не вердикт: основной вердикт H2 (§5) уже вынесен и не меняется.

**Требования (тест до кода):**
1. `Admission.random_frac` / `random_seed`: решение детерминировано по (seed, sym, ts).
2. Доля допущенных ≈ `frac` на большом пуле.
3. `max_per_day` действует поверх случайного отбора.

## 9. Результат — 2026-10-10 (`trader/experiment_h2.py`, `trader/runtime/experiments/h2_selectivity_1010.json`)

Тесты (`trader/test_h2_selectivity.py`) написаны до кода: 12 из 13 упали на старом коде. Тест
`max_per_day` прошёл сразу, механизм уже был.

Пул: 5 602 входа на сетке и 66 279 кандидатов вместе с blocked.

**Обучение** (03-03..06-29, база P-1 на всех входах: −0.727%/день, 1 749 сделок):
- **все 54 кандидата теряют деньги** — дневная R от −0.017 до −0.678%/день;
- парная разница с базой положительна у всех 54 (+0.05…+0.70), нижняя граница выше нуля у 46: отбор
  режет число сделок и вместе с ним убытки;
- победитель `all_candidates|ranker_final_score|q0.50|cap3`: порог -0.247, 173 сделок, R -0.029%/день,
  парная разница +0.685 [+0.195, +1.128].

**Проверка** (07-01..10-09, открыта один раз, k = 1):

| | значение |
|---|---|
| победитель, R | **-0.111%/день [-0.201, -0.013]**, сложный -10.7%, просадка -11.0% |
| сделок / чистый результат сделки | 268 / **-0.417% [-0.749, -0.015]** |
| база (P-1 на всех входах) | -0.616%/день, просадка -54.8% |
| чемпион (выходы бота) | -1.172%/день |
| парная разница с базой | +0.505 [-0.078, +1.059] |
| проскальзывание 0 / 20 б.п. | -0.0685 / -0.1741%/день |

**Вердикты:**
- `improves` = **нет**: нижняя граница парной разницы < 0, месяцы и просадка в норме;
- `profitable` = **нет**: средняя R < 0, интервал чистого результата сделки целиком ниже нуля.

**Чтение.** Отбор по оценкам бота не находит прибыльных сделок. Он лишь сокращает их число: 3 в
день вместо ~25, и убыток в день уменьшается в той же пропорции. Чистый результат отобранной
сделки (−0.42%) не лучше, чем у всех сделок (−0.44% у базы в E1 §12). Оценки бота обучены на
ранний вход и пик, а не на деньги (E2). Чемпионом остаётся «не торговать».

**Справочный контроль §8** (`trader/experiment_h2_control.py`,
`trader/runtime/experiments/h2_random_control_1010.json`, запущен 10-11). Случайный отбор с той же
долей допуска (0.103 пула) и лимитом 3 в день, 20 зёрен:

| половина | победитель R / сделка | случайный, медиана R [мин..макс] / сделка | победитель лучше случайных |
|---|---|---|---|
| обучение | -0.029 / -0.210 | -0.146 [-0.224..-0.080] / -0.552 | 100% (R), 100% (сделка) |
| проверка | -0.111 / -0.417 | -0.127 [-0.213..-0.073] / -0.462 | 75% (R), 70% (сделка) |

На обучении победитель обходит все 20 случайных вариантов, но там он и выбран. На проверке — 75% и
70%: **оценка ранкера по деньгам от случайного отбора не отличима.** Всё, что H2 дал против базы,
даёт и случайное сокращение торговли.
