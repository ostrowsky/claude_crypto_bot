# EX-RL1 — исполнение входа: рыночный ордер или лимитный с таймаутом. Фаза 0 (офлайн), предрегистрация

Дата: 2026-10-29. Решение оператора: «продолжай в соответствии со своими рекомендациями. цель — найти инструменты
повышения прибыльности бота». Источник: `reports/Аналоги ботов и RL в трейдинге.md`. Там исполнение — единственная
область, где у RL есть доказательства (Nevmyvaka et al. 2006, Ning et al. 2021). Офлайн, трейдер (`trader/`), торговля
не меняется. **Загрузка ленты сделок — после отдельного «да» оператора** (§2.2).

## 1. Вопрос и ожидание

Исполнитель входит рыночным ордером. По сверке «демо против бумаги»:
- проскальзывание от цены сигнала в среднем +7.8 б.п., медиана 0;
- у 11 входов |проскальзывание| > 60 б.п.;
- медианная задержка 26 с.

На споте VIP0 комиссия мейкера и тейкера одинаковая (0.10%), поэтому лимитный ордер экономит только спред и
проскальзывание. За это он платит неисполнением: цена может уйти вверх без нас. Опаснее неблагоприятный отбор —
исполняются как раз те входы, после которых цена идёт вниз.

**Вопрос фазы 0:** даёт ли лимитный вход у лучшего бида, с таймаутом, положительную парную разницу денег против
рыночного входа на сделках книги X4 после выхода X4?

**Ожидание, записано заранее:**
- выигрыш не больше ~8 б.п. на вход;
- знак выручки X4 не меняется: в лучшем случае с −0.31 % до ~−0.23 % на сделку.

Это инструмент снижения издержек, а не источник преимущества. RL (обучаемый бандит) нужен, только если в фазе 0
какая-то рука выигрывает хотя бы в части контекстов.

## 2. Данные

### 2.1. Входы
Сделки книги X4 (`execution_replay.run` с политикой `X4_p1_floor8`, движок E1), то есть та популяция, которую торгует
исполнитель:
- входы бота на 15m-сетке с 2026-03-01 по 2026-10-28;
- момент решения t — закрытие сигнального бара;
- выход — момент выхода X4.

Для калибровки симулятора отдельно берутся живые демо-входы исполнителя с 2026-10-20: строки `real_entry` / `enter`,
известна фактическая цена исполнения (§4.1).

### 2.2. Лента сделок (загрузка — после разрешения)
- Публичный REST `GET https://api.binance.com/api/v3/aggTrades?symbol&startTime&endTime&limit=1000`.
- Окно [t, t + 17 мин] на каждый вход.
- Хранится в `trader/runtime/tape/<PAIR>/<t>.npz`: время, цена, количество, `isBuyerMaker`.
- Объём: около 4–5 тыс. входов × 1–3 запроса. Вес `aggTrades` небольшой, темп ≤ 5 запросов/с.

## 3. Руки (заморожено)

L = 30 с — задержка решения, близкая к живой медиане 26 с.
- **A0, рыночный ордер.** Цена — первая сделка покупателя-тейкера (`isBuyerMaker = false`) в момент t + L или
  позже. Комиссия 0.10 %.
- **A1, лимит 2 мин, затем рынок.**
  - Лимитная цена p — цена последней сделки продавца-тейкера (≈ лучший бид) до момента t + L.
  - Исполнение консервативное: в (t + L, t + L + 2 мин] прошла сделка по цене строго ниже p. Значит, нашу очередь на
    уровне p точно прошли.
  - Иначе — рыночный вход по первой сделке покупателя-тейкера после t + L + 2 мин.
  - Комиссия 0.10 %.
- **A2, лимит 15 мин, иначе без сделки.** Те же правила; если исполнения нет, сделки нет.

Выход у всех рук одинаковый — выход X4 этой сделки по той же цене. Руки различаются только ценой входа и фактом входа.

## 4. Проверки и статистики

### 4.1. Калибровка симулятора (условие продолжения)
На живых демо-входах сравниваются:
- цена A0, посчитанная по ленте с L = фактической задержке входа;
- фактическая цена исполнения на демо.

Условие: медиана |разницы| ≤ 15 б.п. Иначе симулятор не годится и фаза 0 останавливается.

Оговорка: книга демо-счёта отличается от живой. Сверка показывает, насколько живая лента объясняет демо-исполнения.

### 4.2. Деньги
Для каждой руки A ∈ {A1, A2} считается парная разница со сделкой A0, в б.п. капитала сделки:
- A1 и исполненный A2: (цена_A0 / цена_A − 1) × (1 + доходность сделки) × 10⁴ ≈ разница цены входа;
- неисполненный A2: −(чистая доходность сделки A0) × 10⁴ — сделки нет.

Ряд по дням — средняя разница дня; блочный бутстрап по дням (`daily_revenue.aggregate`), α = 0.025 на две руки.

Отдельно публикуются:
- доля исполненных и медиана времени до исполнения;
- **неблагоприятный отбор:** средняя чистая доходность X4 исполненных и неисполненных лимитов A2;
- разбивка по месяцам.

### 4.3. Допуск к фазе 1 (shadow-лог на живом исполнителе, отдельная спека)
Рука допускается, если выполнены все условия:
1. калибровка §4.1 пройдена;
2. нижняя граница ДИ средней парной разницы > 0 б.п.;
3. изменённых сделок ≥ 100;
4. в ≥ 5 из 8 месяцев средняя разница ≥ 0.

Ни одна рука не допущена → рыночный вход остаётся, результат коммитится.

## 5. Тесты (до кода, `trader/test_exec_tape.py`)

1. **A0:** первая сделка покупателя-тейкера не раньше t + L; сделки продавца-тейкера пропускаются; ленты нет → нет
   цены.
2. **A1:** лимит = последняя сделка продавца до t + L; исполнение только при сделке строго ниже лимита в окне;
   иначе рынок после таймаута.
3. **A2:** неисполненный лимит → сделки нет, в разницу идёт −доходность сделки.
4. **Парная разница и ряд по дням:** знак (дешевле вход → плюс); неисполненный A2 у убыточной сделки даёт плюс.
5. **Калибровка:** медиана |сим − факт| в б.п.; порог 15 б.п.
6. **Загрузчик ленты:** только GET на `api.binance.com/api/v3/aggTrades`; окно ≤ 1 ч на запрос; страницы по
   `fromId`/времени без дублей; повторный запуск не качает уже сохранённое.
7. **Допуск §4.3** по четырём условиям.
