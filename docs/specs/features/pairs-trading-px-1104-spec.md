# PX — рыночно-нейтральная торговля парами (стат-арбитраж): предрегистрация

Дата: 2026-11-04. Решение оператора: «да, начинай PX». Офлайн, трейдер (`trader/`). Загрузки нет.

## 1. Вопрос

Все направленные гипотезы проиграли рынку или случайному выбору. PX не ставит на направление рынка, он ставит на
схождение спреда.

**Вопрос:** две сильно связанные монеты разошлись. Если купить спот отставшей и зашортить перп ушедшей вперёд, принесёт
ли схождение спреда деньги после издержек обеих ног и фандинга?

**Априорно шансы низкие.** Круг стоит около 0.46% капитала ноги: 2 × (0.10% + 8 б.п.) на споте и 2 × (0.05% + 8 б.п.) на
перпе. Схождение должно быть больше.

## 2. Данные

- **Трейн 2023-03-01..2025-12-31:** кэш рынка FC (`experiment_fc.load_market`): дневной спот, дневной перп, фандинг.
- **Отложенный период 2020-02-01..2022-12-31:** `archive_bh.load_wide_market()` (157 перпов, фандинг). Один взгляд,
  только для победителя трейна.
- **Окно 2026** — один раз, решением оператора.

## 3. Правило (заморожено)

- **Пул дня d:** первые 30 пар `carry.eligible` (ликвидность спота, есть перп и фандинг). Видны только дни < d.
- **Пары:**
  - все пары (a, b) из пула с корреляцией дневных лог-доходностей спота ≥ 0.80 за F дней до d;
  - спред s = log(спот a) − log(спот b), коэффициент 1;
  - z = (s(d − 1) − среднее за F дней) / ст. откл. за F дней.
- **Вход** при |z| ≥ z_in. Лонг спота дешёвой ноги, шорт перпа дорогой; номинал N на каждую ногу, перп изолированный,
  L = 1.
  - Если подходит больше пар, чем свободных слотов, берутся пары с наибольшим |z|.
  - Монета может стоять только в одной открытой паре.
- **Выход** при первом из условий:
  - |z| ≤ 0.5 — схождение;
  - |z| ≥ 4 — стоп;
  - прошло 20 дней;
  - одна из монет выпала из данных — делистинг, по последней цене.
- **Исполнение:** решение по закрытиям до d − 1, сделка по закрытию первого 15m-бара дня d (`first_close`), как в
  `carry.simulate`.
- **Издержки и фандинг:**
  - спот — `carry.fees(1)`: 0.10% + 8 б.п.; перп — 0.05% + 8 б.п. на каждую сделку;
  - шорт перпа получает или платит фандинг за каждое событие внутри удержания.
- **Книга:** 1 000 000 USDT, 10 слотов. Капитал слота равен 2N: спот N плюс маржа перпа N. Дневная отметка по последним
  ценам.
- **Кандидаты (4):** F ∈ {30, 60} × z_in ∈ {2.0, 2.5}. Имя `PX_F{30|60}_Z{20|25}`.

## 4. Контроли и допуск на трейне (все условия, α = 0.05 / 4)

1. Дневной R книги: нижняя граница ДИ > 0. Бутстрап блоками по 5 дней.
2. Средний R больше p95 случайного контроля. Контроль — те же дни входа и те же удержания, но пара случайная из пула
   того дня, направление случайное. 50 сидов.
3. Не меньше 2 из 3 лет со средним R ≥ 0.
4. Сделок ≥ 100.
5. Ликвидаций 0.
6. PBO по 4 кандидатам < 0.5. С 4 кандидатами PBO мало что значит, поэтому он только публикуется.

- **Победитель** — допущенный кандидат с наибольшим R.
- **Отложенный период** (α = 0.05): R нижняя граница > 0 и больше p95 случайного контроля.
- Нет победителя → STOP, запись в `already_tried.jsonl`.

Рядом публикуются средняя сделка до и после издержек, доля сходящихся пар и вклад фандинга. Так видно, где теряются
деньги.

## 5. Тесты (до кода, `trader/test_px.py`)

1. z-оценка спреда: только дни до d, окно F; при F дней без пропусков значение совпадает с ручным расчётом.
2. Отбор пар: порог корреляции, одна монета — одна пара, порядок по |z|, лимит слотов.
3. Сделка: лонг дешёвой и шорт дорогой ноги, издержки обеих ног, фандинг шорта.
4. Выходы: схождение, стоп, 20 дней, делистинг.
5. Случайный контроль: те же дни и удержания, воспроизводимо по сиду.
6. Допуск §4 по каждому условию.
