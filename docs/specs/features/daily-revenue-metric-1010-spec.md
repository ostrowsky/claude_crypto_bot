## 1. Зачем отдельная спека

Метрику фиксируем **до** первой сделки. Иначе её определение подгоняется под первые цифры. Так уже
было в проекте: recall@20 = 100% без базовой частоты, North Star на протекающих метках. Её
используют этап D (учёт), E (критерии гейта), F (L1–L3) и утренний отчёт. Определение меняется
только новой версией (v2, v3…), старая продолжает публиковаться рядом (TH-04).

## 2. Определение

**Капитал** `E(t)` — сумма всех активов демо-счёта (`free + locked`, включая заблокированные в
ордерах) × mid-цена в USDT в момент t:
- USDT = 1;
- актив без пары к USDT → через BTC;
- актив без цены → в `unpriced` с количеством и долей. Если доля unpriced > 0.1% капитала, день
  получает статус `UNKNOWN`.

**Дневная выручка**:

```
R_d = (E(00:00 UTC d+1) − E(00:00 UTC d) − T_d) / E(00:00 UTC d)
```

`T_d` — переводы и сбросы демо-баланса за сутки. Комиссии, проскальзывание и переоценка открытых
позиций входят автоматически, потому что метрика считается по капиталу, а не по закрытым сделкам.

**Два независимых способа расчёта** (§5.4 целевой спеки «пересчёт из сырых данных»):

| способ | источник | роль |
|---|---|---|
| P (primary) | `equity_snapshots.jsonl`: каждые 5 мин и на закрытии UTC-суток, `GET /api/v3/account` + цены | значение метрики |
| L (ledger) | капитал начала дня + Σ исполнений из журнала и `myTrades` − комиссии + переоценка остатка по ценам закрытия | проверка |

Если |P − L| > 0.01% капитала, день получает статус `RECONCILE_FAIL`: тревога, в агрегаты не
входит.

## 3. Статусы дня (TH-05: отсутствие данных — не провал)

| статус | условие | в «результат счёта» | в атрибуцию политике |
|---|---|---|---|
| `FULL` | снимки на обеих границах, сверка прошла, бот жив ≥ 95% минут | да | да |
| `BOT_DOWN` | капитал известен, бот жив < 95% минут (позиции жили с защитой на бирже) | да | **нет** |
| `RESET` | сброс/пополнение демо-баланса (остаток P − L не объясняется исполнениями) | нет | нет |
| `UNKNOWN` | нет снимка на границе и нет восстановления по журналу, или unpriced > 0.1% | нет | нет |
| `RECONCILE_FAIL` | см. выше | нет (тревога) | нет |

Время жизни бота считается по `_compute_early_capture.load_uptime` (тот же источник, что у North
Star). Сброс баланса из UI демо-счёта оператор отмечает командой `/reset_noted` в Telegram. Без
неё сброс определяется по остатку.

## 4. Агрегаты и формулировки

За 7 / 30 / все дни (только `FULL` + `BOT_DOWN`; число исключённых дней печатается рядом):
- **средняя R** с 95% ДИ, блочный бутстрэп по дням (блок 5 дней: дни зависят друг от друга
  через открытые позиции и режим рынка);
- **сложный результат** `Π(1 + R_d) − 1`;
- **макс. просадка** по кривой капитала (не по сумме процентов);
- доля прибыльных дней, худший день, средняя экспозиция (доля капитала в позициях);
- **бенчмарки за те же дни:** USDT (0), BTC buy&hold, равновзвешенный торговый универсум
  (дневная доходность закрытие-к-закрытию), плюс разница с каждым.

Правила текста отчёта, машинно проверяемые (TH-09, TH-10):
1. Слова «растёт / падает / лучше / хуже» допустимы, только если 95% ДИ разницы не включает 0 и
   окна сравнимы: одинаковое число дней в статусах `FULL`+`BOT_DOWN`, ±10%. Иначе — «рано
   судить».
2. Любое число выручки печатается вместе с n дней, ДИ и бенчмарком. Строка без них —
   блокирующая ошибка `truth_harness`.
3. Реплей и факт не сворачиваются в одно число (§0 правило 3). Реплей-оценка дня печатается
   рядом с фактом как «разрыв реплей ↔ факт».

## 5. Разложение (для L1 аналитика)

```
R_d ≈ Σ_сделок w_i × (g_i − f_i − s_i) / E  +  переоценка открытых
  w_i  размер позиции, g_i  результат до комиссий, f_i  комиссия, s_i  проскальзывание
```

Публикуется по дню и окну: сделок, доля прибыльных, средний выигрыш и проигрыш, Σ комиссий,
Σ проскальзывания (факт против цены сигнала), экспозиция. Срезы: режим входа, причина выхода
(TP / SL / трейл / лидер / слабость / таймаут / аварийный стоп), режим рынка (бычий день, BTC
против EMA50).

## 6. KPI обучения (что контур оптимизирует между длинными окнами)

| KPI | определение | почему |
|---|---|---|
| чистое ожидание сделки | среднее `(g − f − s)` по сделкам, 95% ДИ | тысячи сделок против сотен дней |
| парная разница политик | `R_d(кандидат) − R_d(чемпион)` в одни и те же дни, теневые портфели с независимым состоянием | общий шум рынка вычитается |
| разрыв реплей ↔ факт | `R_d(реплей решений дня) − R_d(факт)` | калибровка модели исполнения |

**Мощность.** На базовой линии sd дневной R = 1.84%: чтобы обнаружить +0.10%/день с мощностью
80%, нужно ≈ 2 650 дней (`_backtest_daily_revenue_baseline.py`). Поэтому изменения судятся по KPI
этого раздела, а дневная выручка — итог длинных окон. Насколько парная разница уменьшает разброс,
измеряется на этапе E7 и записывается сюда.

## 7. Базовая линия (реплей, не эта метрика)

`_backtest_daily_revenue_baseline.py`, 5 753 реальные сделки 03-03..10-10, 10 равных слотов,
только реализованный результат по дате выхода: −0.83%/день (комиссия 0.20% за круг), sd 1.84%,

нет проскальзывания, нет капитала счёта. Первое значение v1 появится на этапе C.
