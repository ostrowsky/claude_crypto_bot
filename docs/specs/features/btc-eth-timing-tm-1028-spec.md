# TM — тайминг BTC/ETH на споте: «в рынке или в USDT» (N1 + N2 + N5), предрегистрация

Дата: 2026-10-28. Источник гипотез: `trader-hypotheses-1028-spec.md` (N1, N2, N5). Ничего не разворачивается:
это офлайн-проверка на истории `trader/runtime/history` (15m спот) и `trader/runtime/funding` (фандинг бессрочных).

## 1. Вопрос

Зарабатывает ли правило тайминга на дневной выручке счёта больше, чем то же время в рынке без тайминга?
Правило раз в сутки решает, какую долю капитала держать в BTC и ETH (остальное в USDT).

Ловушка, ради которой построены критерии: 2023–2025 — бычий рынок BTC. Любое правило «чаще в рынке» на трейне
выглядит хорошо. Поэтому сравнение идёт не с нулём, а:
- с **CE** — постоянной долей, равной средней доле правила (то же время в рынке, без тайминга);
- со **случайным таймингом** — циклическим сдвигом той же последовательности долей.

## 2. Данные и окна

- Дневные бары BTCUSDT и ETHUSDT из 15m (`xsmom.daily_from_15m`):
  - close — закрытие последнего 15m-бара суток;
  - first_close — закрытие бара 00:00; по нему исполняется сделка дня.
- Фандинг BTCUSDT/ETHUSDT бессрочных (`funding_store.load_funding`). В сигнал дня d входят только выплаты
  с t < 00:00 UTC дня d.
- **Трейн:** решения 2023-03-01 .. 2025-12-31; панель обрезана до 2026-01-01, ни один бар 2026 не читается.
- **Тест:** 2026-01-01 .. вчера, открывается один раз (маркер `TM_TEST_OPENED.json`), только по решению оператора,
  только для победителей трейна. Тест 2026 для тайминга BTC **не вполне слепой**: рынок 2026 года прожит
  оператором и мной. Поэтому принятие на тесте ведёт только в теневую книгу вперёд, не в деньги.

## 3. Портфель и деньги

- Два рукава по 50% начального капитала: BTC и ETH, каждый со своим сигналом. Капитал 1 000 000 USDT,
  чтобы минимальный объём ордера не связывал.
- День d:
  1. отметка капитала в 00:00 по close дня d−1;
  2. целевая доля w ∈ [0, 1] по данным строго до d;
  3. ребалансировка по first_close дня d, если |w − w_тек| > 0.10. Переход 0↔1 всегда больше полосы.
- Исполнение: `fill_model.model("taker", 1)`, то есть тейкер 0.10% + 8 б.п. на сторону. Чувствительность —
  BNB 0.075% и проскальзывание уровня 2 (20 б.п.), только для справки.
- Выручка дня R_d — изменение отметки 00:00→00:00, `daily_revenue.aggregate`. В конце окна последняя отметка
  ставится, затем всё продаётся (как в XSMOM).
- Мало данных для сигнала (начало истории) → w = 1. «Нет данных — нет блокировки», как `xsmom.market_on`.
  В первые месяцы такое правило равно «купи и держи».

## 4. Кандидаты (20, заморожено)

**Ряд T (N1, тренд), 10 кандидатов:**
- `T_ret_N`: w = 1, если close[d−1] / close[d−1−N] − 1 > 0, иначе 0;
- `T_sma_N`: w = 1, если close[d−1] > среднего close за N дней [d−N, d−1], иначе 0;
- N ∈ {7, 14, 28, 56, 112}.

**Ряд V (N2, объём обратно волатильности), 6 кандидатов `V_N_k`:**
- σ̂_N — стандартное отклонение дневных лог-доходностей за последние N дней (до d);
- σ* = k × медиана всех σ̂_N, посчитанных на днях до d (расширяющееся окно; меньше 60 значений → w = 1);
- w = min(1, σ* / σ̂_N);
- N ∈ {7, 14, 30}, k ∈ {0.75, 1.0}.

**Ряд F (N5, перегрев по фандингу), 4 кандидата `F_W_q`:**
- f — средняя ставка фандинга за последние W дней до 00:00 d;
- порог — квантиль q всех дневных значений f до d (расширяющееся окно; меньше 90 значений → w = 1);
- w = 0, если f > порога, иначе 1;
- W ∈ {3, 7}, q ∈ {0.80, 0.90}.

## 5. Контроли и сравнения

- **CE** — постоянная целевая доля, равная средней целевой доле кандидата по окну на каждом рукаве; та же полоса
  0.10, те же издержки.
- **Случайный тайминг** — 50 сидов. Последовательность целевых долей каждого рукава циклически сдвигается на
  случайное смещение в [30, n − 30] дней, отдельно на каждом рукаве. Сдвиг сохраняет долю времени в рынке,
  число переключений и длины серий, но рвёт связь с будущим.
- **BH** — «купи и держи» тех же рукавов (w = 1), для справки.
- **FC_PASSIVE** — для справки на тесте (`carry-funding-money-1021-spec.md`).

## 6. Допуск на трейне (все условия, заморожено)

1. mean R кандидата > p95 средних R случайного тайминга;
2. парная разница с CE: mean > 0;
3. годы: парная разница с CE ≥ 0 хотя бы в 2 из 3 лет (2023, 2024, 2025);
4. ребалансировок за трейн ≥ 12 (сумма по рукавам).

**Отбор.** PBO (CSCV, 8 частей) по каждому ряду T, V, F на дневных рядах R. Ряд открыт, если PBO < 0.5.
Победитель ряда — допущенный кандидат с наибольшей парной разницей с CE. Победителей не больше 3 (по одному на ряд).
Deflated Sharpe считается для справки (число испытаний — 20).

Нет допущенных или все ряды закрыты → **STOP**: тест не открывается, семейство записывается как отвергнутое на трейне.

## 7. Решение на тесте (заморожено)

При k открытых победителях α = 0.05 / k. Кандидат **ПРИНЯТ**, если выполнены все три условия:
1. R теста: нижняя граница ДИ (1 − α) > 0 — счёт зарабатывает больше USDT;
2. парная разница с CE: нижняя граница ДИ (1 − α) > 0;
3. mean R > p95 случайного тайминга.

Принятие означает только теневую книгу вперёд рядом с FC_PASSIVE, не деньги. Отказ на любом условии → отвергнут,
записывается в `already_tried.jsonl` с числами.

## 8. Тесты (пишутся до кода, `trader/test_timing_tm.py`)

1. Нет заглядывания: изменение строк ≥ d не меняет целевую долю дня d (T, V, F).
2. Фандинг: выплата в 00:00 дня d и позже не входит в сигнал дня d.
3. Без издержек BH воспроизводит отношение цен рукавов.
4. Без издержек вкл/выкл даёт произведение дневных доходностей дней «в рынке».
5. Сохранение денег: итог − старт = сумма pnl сделок; после окна нет позиций.
6. Полоса 0.10: смещение доли на 0.05 не торгуется, на 0.20 торгуется.
7. Случайный сдвиг сохраняет долю времени в рынке и число переключений вкл/выкл.
8. CE держит среднюю долю кандидата.
9. Допуск и отбор: правила §6 на синтетических результатах; нет победителей → нет маркера; повторное открытие теста —
   ошибка; тест без трейна — ошибка; `test` без `--operator-approved` не запускается.
10. Панель трейна не содержит строк ≥ 2026-01-01.
