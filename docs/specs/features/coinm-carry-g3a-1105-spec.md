# G3a: carry на COIN-M (инверсный перп, монета как маржа) против FC_PASSIVE

Дата: 2026-11-05. Решение оператора: «да, загружай для G3a». Трейдер (`trader/`). Спека коммитится отдельно, до загрузки
данных и до расчётов.

## 1. Вопрос

У FC_PASSIVE при L = 1 половина капитала лежит без дохода в USDT-марже: номинал N = C / 2. В COIN-M спот-монета сама служит
маржой под шорт инверсного перпа, поэтому номинал N = C, а фандинг идёт почти на весь капитал. Ставка на COIN-M при этом
может быть другой.

**Гипотеза:** COIN-M carry на BTC и ETH приносит на единицу капитала больше, чем FC_PASSIVE, при тех же правилах и издержках.

## 2. Данные

- **Загрузка** (`data.binance.vision`, решение оператора): `data/futures/cm/monthly/fundingRate/{BTCUSD_PERP,ETHUSD_PERP}/` — 96 файлов,
  0.08 МБ; `data/futures/cm/monthly/klines/{BTCUSD_PERP,ETHUSD_PERP}/15m/` — 150 файлов, 19 МБ. Хранение: `trader/runtime/coinm/`.
- **Спот:** `history_store`, BTCUSDT и ETHUSDT, 15m.
- **Окно:** train 2023-03-01..2025-12-31, тот же, что у FC_PASSIVE. **2026 не открывается**, это отдельное решение оператора. Фандинга в
  месячном архиве 48 файлов, поэтому начало ряда будет проверено при загрузке; если он не покрывает окно, это записывается.

## 3. Правило (заморожено)

- **Пары:** BTC и ETH, капитал поровну.
- **Вход:** по закрытию первого 15m-бара дня: покупка спота на весь капитал пары, монета — маржа; шорт инверсного перпа на номинал той
  же стоимости по цене перпа.
- **Учёт пары в монете:** монета + N · (1/f_t − 1/f_e); стоимость в USD — монета × спот. Переоценка на закрытие первого 15m-бара дня.
- **Фандинг:** при ставке > 0 шорт получает в монете rate · N / f за каждое начисление. Цена — перп на момент начисления
  (15m-close бара, в котором оно случилось).
- **Перехеджирование:** раз в день; прибыль шорта фиксируется в монете, новый номинал N = монета · f_t. Сделка только если изменение
  N ≥ 0.5%; издержки на |ΔN|.
- **Выход:** по окончании окна: продажа спота и закрытие шорта.
- **Издержки — как у FC_PASSIVE (`carry.fees(1)`):** спот 0.10%, перп 0.05%, проскальзывание 8 б.п. на сторону на каждой ноге. Размер
  контракта (100 USD BTC, 10 USD ETH) не моделируется: это раскрыто.
- **Ликвидация:** при L = 1 с маржой в той же монете потеря шорта ограничена N / f_e = монете. Отдельно отслеживается, не падала ли
  маржа ниже 1% стоимости позиции.

## 4. Критерий

Бенчмарк — `experiment_fc.evaluate(passive_config, carry.fees(1))` на тех же днях (+0.0111 %/день, ~4 %/год).

Переход к предложению взгляда на 2026 — только если одновременно:
1. парная разность COIN-M − FC_PASSIVE: нижняя граница > 0, блок 20 дней, α = 0.05;
2. разность положительна минимум в 2 годах из 3;
3. нет эпизода с маржой ниже 1%.

Отдельно записывается главный вопрос ревизии: средняя ставка COIN-M против USDⓈ-M на тех же днях (разность с ДИ), средний номинал на
капитал, годовые результаты, просадка и издержки.

Иначе — запись «нет прироста» и СТОП.

## 5. Тесты (до кода, `trader/test_coinm.py`)

1. Нейтральность: при неизменной базе и нулевых издержках и фандинге стоимость в USD не зависит от цены монеты, в том числе при
   движении ±50%.
2. Знак фандинга: шорт при ставке > 0 получает, при < 0 платит, в монете.
3. Перехеджирование: срабатывает только при изменении N ≥ 0.5%; издержки только на |ΔN|.
4. Вход и выход платят обе ноги с нужными издержками.
5. Деньги сохраняются: итог = старт + фандинг + изменение базы − издержки.
6. Парсер месячных файлов COIN-M: свечи и фандинг.
