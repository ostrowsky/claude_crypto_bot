результат в деньгах, — **выход** (H3).

## 2. Какие методы рассмотрены и почему выбраны эти

Методу нужно, чтобы в данных была информация. Если её нет, RL ровно так же найдёт шум, как и
классификатор, только дороже и менее заметно.

| метод | что даёт | подходит ли сейчас | решение |
|---|---|---|---|
| **Глубокий RL end-to-end** (PPO / DQN / SAC по ценовому ряду, решает вход, размер и выход) | один агент на всё | **нет.** Нестационарный рынок, ~10 сделок в день живьём, сильная подгонка под симулятор. В литературе результаты вне выборки плохо воспроизводятся. На входах нет сигнала (§1), агент будет учиться на шуме | **не делаем** |
| **Offline RL для выхода** (fitted-Q, с консервативной поправкой на неисследованные действия, по образцу CQL) | решение «держать / выйти» на каждом баре позиции по состоянию: нереализованный результат, бары в позиции, волатильность, расстояние до трейла, режим рынка | **да.** Рычаг выхода доказан (H3); путей позиций миллионы (2 млн кандидатов × 96 баров с 2023 г., `trader/runtime/history`); награда — деньги после издержек из движка E1 | **F2** |
| **Мета-разметка** (López de Prado): вторая модель решает, брать ли сигнал бота и каким размером, метка — тройной барьер | фильтр и размер входа | **только с новыми признаками.** E2 — это уже мета-разметка на признаках бота, и она отвергнута. Новые данные — микроструктура в момент входа: спред, стоимость стакана, расхождение демо и рынка (`runtime/microstructure`, с 10-10) и фактическое проскальзывание C2 | **F3**, после ≥ 30 дней данных |
| **Контекстный бандит / Thompson-выбор политики** над книгами-кандидатами | какую из проверенных политик исполнять, обучается на живой дневной выручке | **да, как надстройка.** Книги теней E7 — готовые «руки» | **F4** |
| **Байесовская оптимизация параметров** (Optuna) | подбор порогов | только как генератор гипотез для L3, не правка конфига | в составе F1 |
| **Новые источники входов** (кросс-секционный моментум, разворот на коротком горизонте, кэрри фандинга) | альфа, а не способ обучения | вне этой спеки: фандинг-кэрри требует фьючерсов, демо — спот | отдельная спека, если оператор решит |

**Защита от самообмана для всех методов:**
- деление по времени со сдвигом (purged walk-forward: строки, чей исход пересекает границу, удаляются, плюс «эмбарго» в 1 день);
- реестр попыток (`trials.jsonl`): поправка на число проверок, вероятность подгонки бэктеста (PBO по CSCV) и дефлированный коэффициент Шарпа, а не просто лучшая точка;
- решение — только в деньгах движка E1 и в тени E7, не по AUC или награде агента (TH-11).

## 3. Что делает контур (F1 — данные и ежедневный цикл)

Каждую ночь, после `run_daily.cmd` (D):

1. **Сделки → набор данных.** `trader/learning/trade_dataset.py` собирает по каждому решению исполнителя
   строку набора `runtime/learning/trades.jsonl`, только добавлением:
   - вход, пропуск или выход, причина;
   - цена события, цена исполнения, проскальзывание, задержка;
   - признаки в момент входа, известные на тот момент: поля события бота, срез микроструктуры ≤ 5 мин до
     входа, позиционирование ≤ 2.5 ч;
   - исход: чистый результат сделки по журналу сделок (myTrades) из D, путь позиции по барам,
     MFE и MAE, причина выхода.
2. **Те же строки — для всех кандидатов, которых не взяли**, с исходом из реплея E1 (контрфактическое
   «если бы вошли»). Живых сделок ~10 в день; обучение идёт на полном наборе кандидатов, а живые сделки
   калибруют модель исполнения (V6) и проверяют, что реплей не врёт.
3. **Сверка «живое против реплея».** По каждой живой сделке — разница результата демо и движка E1 на тех же
   барах. Метрика расхождения публикуется в отчёте (§0 правило 3: расхождение обучения и деплоя — главная
   диагностика).
4. **Обучение кандидатов** (F2, F3) на максимальном периоде с purged walk-forward. Результат — гипотеза в L3,
   не правка.
5. **L3 в деньгах** (`money_validator`): заранее записанный критерий, учёт попыток, PBO.
6. **Продвижение только через тень:** L3 accept → новая книга E7 → разбор с заранее записанным критерием
   → решение оператора → `policy_epoch` исполнителя. Автопродвижение — решение оператора №3
   (дорожная карта §5), пока не принято.

## 4. F2 — обучаемый выход (offline RL), первый метод

- **Состояние на баре t позиции:**
  - нереализованный результат;
  - бары в позиции;
  - MFE с начала позиции;
  - ATR%;
  - расстояние до трейла X4 в ATR;
  - доходность монеты с открытия UTC и её место в дне;
  - BTC против EMA200 15m и ширина рынка (`trader/regime.py`);
  - режим входа бота.

  Только данные ≤ t.
- **Действия:** держать / выйти по закрытию бара. Аварийный стоп на бирже остаётся всегда.
- **Награда:** изменение стоимости позиции за бар; при выходе — издержки уровня 1 (taker + 8 б.п.).
- **Метод:**
  - fitted-Q iteration с градиентным бустингом (LightGBM/CatBoost — то, что уже есть в окружении);
  - консервативная поправка: «выйти» выбирается, только если Q(выйти) − Q(держать) > δ, а δ подбирается на
    валидации, без проверки;
  - ограничение снизу: правило не держит дольше 96 баров и не снимает трейл X4. Агент может только выйти
    **раньше** X4.
- **Данные:**
  - обучение — пути позиций по входам генератора B на W93 2023–2025 (тот же пул, что B3);
  - проверка политики выхода — реальные входы бота 07-01..последний день в движке E1, против X4;
  - проверка открывается один раз.
- **Вердикт:**
  - `improves` против X4: парная разница дневной R, нижняя граница > 0, ≥ 60% месяцев ≥ 0, ≥ 200 сделок;
  - `beats_random_exit`: лучше, чем выход в случайный бар с той же долей ранних выходов;
  - `profitable`.

  При `improves` без `profitable` — книга в тень E7, не в исполнитель.

**Почему именно выход, а не вход.** Выход — единственный рычаг с доказанным эффектом в деньгах (H3). Путь
позиции, в отличие от признаков входа, содержит информацию о сделке: MFE, откат, скорость. И ограничение
«только раньше X4» не даёт агенту потерять то, что X4 уже зарабатывает на ракетах.

## 6. Тесты (до кода, F1 + F2)

1. **Набор сделок:**
   - каждая строка исполнителя даёт ровно одну строку набора;
   - признаки только с метками времени ≤ входа (срез позже входа отбрасывается);
   - исход берётся из журнала D;
   - повторный запуск не дублирует строки (идемпотентность по `decision_id`);
   - битые строки пропускаются.
2. **Сверка «живое против реплея»:** на синтетике разница = 0, когда исполнение совпадает с баром; знак и
   размер верные при проскальзывании.
3. **Purged walk-forward:** строка, чей исход пересекает границу, удалена; эмбарго 1 день; ни одна
   тестовая метка не видна обучению.
4. **Fitted-Q:**
   - на синтетике с известным оптимумом (детерминированный разворот после пика) правило выходит на
     пике ± 1 бар;
   - на случайном блуждании без сноса не выходит раньше X4 чаще, чем задаёт δ;
   - не держит дольше 96 баров;
   - не выходит позже трейла X4.
5. **Реестр попыток и PBO:** CSCV на синтетике с одной настоящей стратегией среди шумовых даёт PBO
   < 0.2; только шум даёт ≈ 0.5.
6. **Граница:**
   - запись только в `trader/runtime/`;
   - бот только читается;
   - проверка F2 открывается один раз (метка).

## 7. Граница вывода

- Демо-рынок отличается от основного: проскальзывание и стакан мерит A0. Выручка C2 при масштабе 0.02 —
  ±0.05 %/день капитала, ожидаемо отрицательная. По 7 дням C2 о политике не судят (`demo-execution-c-1013-spec.md` §8).
- Даже принятый F2 не делает систему прибыльной сам по себе: X4 ≈ −0.25…0 %/день. F2 может сократить
  убыток или вывести книгу в ноль; прибыль требует источника входов с информацией (§1, §2 последняя строка).

### F2 runner — контракт (2026-10-20, до тестов)

Окна зафиксированы до запуска. Ни одно не пересекается с другим.

| часть | данные | для чего |
|---|---|---|
| обучение | пути позиций по входам генератора B на W93, `ts < 2026-01-01` (кэш `b3_cands`, сетка `lazy_grid`) | обучение `ExitPolicy` |
