# QB — квартальный базис BTC/ETH: спот в лонг + квартальный фьючерс в шорт до экспирации (N3), предрегистрация

Дата: 2026-10-29. Источник: `trader-hypotheses-1028-spec.md`, N3. Решение оператора 2026-10-29: «разрешаю» — шорт
и загрузку истории фьючерсов. Офлайн-проверка, ничего не разворачивается.

## 1. Механизм и вопрос

Квартальный фьючерс USDⓈ-M обычно торгуется с премией к споту. При экспирации премия сходится к нулю.
Купив спот и продав фьючерс, к экспирации получаешь премию на входе минус издержки, независимо от направления цены.
Неизвестны только маржа шорта по пути и разница цен закрытия на экспирации.

FC_PASSIVE держит то же «спот + шорт», но на бессрочном и получает фандинг. Отличие QB: доход **фиксируется при
входе**.

**Вопрос:** даёт ли QB положительную дневную выручку с ДИ выше нуля, и насколько она отличается от FC_PASSIVE на тех же
днях?

## 3. Правило (заморожено)

- **Когда решается.** Раз в сутки, по закрытию часа 00:00–01:00 UTC, отдельно по BTC и по ETH. Половина капитала на
  пару.
- **Контракт.** Ближайший квартальный, до экспирации которого не меньше 14 дней.
- **Сигнал.** `basis_ann = (F / S − 1) × 365 / дней_до_экспирации` по закрытиям этого часа.
- **Вход**, если позиции по паре нет и `basis_ann ≥ θ`:
  - купить спот на N, продать фьючерс на то же количество;
  - изолированная маржа при плече 1 равна N, то есть N = капитал_пары / 2, как в FC при L = 1.
- **Выход — только на экспирации.** Обе ноги закрываются по закрытию часа 07:00–08:00 UTC в день экспирации.
  Расчётная цена — среднее индекса за последние 30 мин, поэтому закрытие этого часа берётся как её приближение.
  Со следующего решения можно войти в следующий контракт.
- **Риск:**
  - ликвидация шорта, если максимум фьючерса ≥ вход × (1 + 1/L − MMR), MMR = 0.01;
  - маржин-стоп, если капитал шорта < 50% маржи, — как в FC.
- **Издержки** — `carry.fees(1)`:
  - спот: тейкер 0.10% + 8 б.п.;
  - фьючерс: тейкер 0.05% + 8 б.п.;
  - на круг 4 ноги.
- **Отметка капитала** в 00:00 UTC: наличные + спот + маржа + (F_вход − F_t) × q.
- **Кандидаты (4).** `QB_T{θ%}`, θ ∈ {0, 5, 10, 15}% годовых; θ = 0 означает всегда в позиции. Капитал 1 000 000 USDT.

## 4. Окна

- **Трейн.** Решения 2023-03-01 .. 2025-12-31. Позиция, открытая в трейне, может досидеть до экспирации 2026-03-27;
  чтобы трейн не читал 2026 год, вход разрешён, только если экспирация < 2026-01-01.
- **Тест.** 2026-01-01 .. последний доступный день. Открывается один раз, только по решению оператора, маркер
  `QB_TEST_OPENED.json`.

## 5. Допуск на трейне (все условия, заморожено)

1. Нижняя граница 95% ДИ R > 0.
2. 0 ликвидаций.
3. R ≥ 0 хотя бы в 2 из 3 лет.
4. Для θ > 0 дополнительно: парная разница с `QB_T0` на тех же днях, mean > 0. Порог должен быть лучше, чем
   «всегда в позиции».
5. PBO по 4 кандидатам < 0.5.

**Победитель** — допущенный кандидат с наибольшим R.

**Справочно, на допуск не влияет:**
- парная разница с FC_PASSIVE на тех же днях (`carry.simulate`, рынок BTC+ETH, как в FS);
- годовая доходность;
- максимальная просадка;
- число контрактов, в которых была позиция.

## 6. Решение на тесте (заморожено, k = 1, α = 0.05)

ПРИНЯТО, если выполнены все условия:
1. нижняя граница ДИ R > 0;
2. 0 ликвидаций;
3. максимальная просадка ≥ −10%.

Принятие означает теневую книгу рядом с FC_PASSIVE, не деньги.

## 7. Тесты (до кода, `trader/test_quarterly_qb.py`)

1. **Экспирации:** последняя пятница квартала, 08:00 UTC; символ `BTCUSDT_YYMMDD` ↔ дата.
2. **Выбор контракта:**
   - ближайший, до экспирации которого ≥ 14 дней;
   - в трейне — только контракт с экспирацией < 2026-01-01.
3. **Базис:** `basis_ann` по формуле §3; решение дня видит только бары, закрытые к 01:00.
4. **Деньги без издержек:** вход и экспирация при F = S × (1 + b) на входе и F = S на экспирации дают R капитала пары
   = b × N / (2N).
5. **Сохранение денег.** После окна позиций нет.
6. **Ликвидация:** при росте максимума до цены ликвидации маржа теряется. Маржин-стоп — как в `carry`.
7. **Порог:** при `basis_ann` < θ вход не делается.
8. **Допуск и маркер:**
   - правила §5;
   - нет победителя → маркера нет;
   - повторное открытие → ошибка;
   - `test` без `--operator-approved` → 2.
