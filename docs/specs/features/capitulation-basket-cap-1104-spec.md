# CAP — покупка рынка после всеобщей капитуляции: предрегистрация

Дата: 2026-11-04. Решение оператора: «да, начинай с CAP и FC-W». Офлайн, трейдер (`trader/`). Загрузки нет: данные
2018–2022 скачаны для BH19, данные 2023–2025 — рабочие хранилища.

## 1. Откуда гипотеза и почему проверка честная

В LQ (`liquidation-flush-lq-1030-spec.md`) средняя сделка после сильного часового падения монеты была +1–2% за 24 ч.
При этом 72–74% суммы дали 5 дней массовых обвалов, а книга на 10 слотов денег не дала. Отсюда гипотеза: преимущество
даёт не падение отдельной монеты, а день всеобщей капитуляции. Ловить его надо покупкой всего рынка, а не отдельных монет.

**Идея родилась на 2023–2025, поэтому решение по этим годам не принимается.** Решающая проверка — на 2018–2022: этот
период идея не видела, правила замораживаются до чтения результатов. Числа 2023–2025 публикуются рядом как источник идеи,
с пометкой «исследовательские».

## 2. Данные

- **2018–2022:** спот 15m из `trader/runtime/history_bh/` (418 пар, включая делистинговые) и BH-панель

- **Вселенная дня d:** `xsmom.universe` — топ-100 по ликвидности за 30 дней, видны только дни < d. Возраст пары не меньше

## 3. Событие и сделка (заморожено)

- **Ширина падения.** На закрытии 15m-бара t считается `breadth_W(t)`: доля пар вселенной, у которых
  log(close(t) / close(t − W)) ≤ −Y. В знаменателе — пары, у которых есть оба бара. Если таких пар меньше 50, бар
  пропускается.
- **Кандидаты (8)** = 2 окна × 2 порога доли × 2 удержания:
  - окно W = 1 ч с падением Y = 5%, или W = 4 ч с Y = 10%;
  - порог доли X ∈ {25%, 50%};
  - удержание H ∈ {24 ч, 72 ч}.
  - Имя: `CAP_W{1|4}_X{25|50}_H{24|72}`.
- **Событие:** `breadth_W(t) ≥ X`. Следующее событие — не раньше конца удержания, сделки не пересекаются.
- **Сделка — корзина с равными весами.**
  - Покупаются все пары вселенной, у которых есть закрытие бара t + 1. Вход по закрытию бара t + 1, выход через H по
    закрытию бара.
  - Издержки `fill_model.model("taker", 1)` на каждую ногу.
  - Пара без бара выхода (делистинг) — убыток −50%, как в `lq.trade`.
- **Доход события** — среднее по парам корзины.

## 4. Статистика и допуск (на 2018-03-01..2022-12-31, все условия, α = 0.05 / 8)

1. Средний доход события после издержек: нижняя граница ДИ > 0. Бутстрап по событиям: они не пересекаются.
2. Средний доход события больше p95 случайного контроля. Контроль — те же месяцы и столько же событий в случайных
   15m-барах, 200 сидов, та же корзина.
3. Не меньше 2 из 3 периодов со средним ≥ 0: 2018–2019, 2020–2021, 2022.
4. Событий ≥ 10.
5. PBO по 8 кандидатам < 0.5, по месячным доходам книги.

**Книга (отчёт, не критерий).** Весь капитал идёт в корзину на время удержания, остальное время в USDT. Публикуются R
(%/день) с ДИ, max DD и доля дней в рынке.

**Мощность — до чтения доходов.** Шаг `plan` считает число событий каждого кандидата и разброс дохода корзины в
случайных барах. Из них — минимальный различимый эффект MDE = z_(1−α/2) × sd / √n. MDE записывается в журнал до
шага `test`.

**Итог.**
- Победитель — допущенный кандидат с наибольшим средним.
- Затем окно 2026 — один раз, решением оператора.
- Победителя нет → STOP, запись в `already_tried.jsonl`.

## 5. Тесты (до кода, `trader/test_cap.py`)

1. **Ширина падения:** доля считается по вселенной дня; бар с меньше чем 50 парами пропускается; будущий бар не влияет.
2. **События:** порог; следующее событие не раньше конца удержания.
3. **Корзина:** вход на баре t + 1, выход через H, издержки, делистинг −50%.
4. **Случайный контроль:** те же месяцы, то же число, воспроизводимо по сиду.
5. **Допуск §4** по каждому условию.

только эффект от ~0.9–3.3% на событие; меньший эффект даст «не доказано», а не «опровергнуто».

отступления, каждое раскрывается:
1. Один взгляд на 2026-01..2026-10, k = 1. Событий там, вероятно, мало, поэтому мощность низкая.
2. Теневая книга вперёд (бумага, без денег). Таких событий около 10–15 в год, читать её — не раньше чем через год.

### 2026-11-04 — решение оператора: «и то и другое: открывай 2026, потом теневая книга»

**Отступление от предрегистрации (раскрыто).** По §4 победителя нет, а значит, нет и окна 2026. Оператор открывает его для
одного замороженного правила, которое ближе всех подошло к допуску. Правило не менялось.

**Взгляд на 2026 — правила зафиксированы до запуска:**
- **Правило:** CAP_W4_X50_H24 без изменений: W = 4 ч, Y = 10%, X = 50%, H = 24 ч, та же корзина, те же издержки.
- **Окно:** события с 2026-01-01 по последний полный день хранилища минус 1 день (удержание 24 ч должно закончиться).
  Перед запуском хранилище 15m и дневная панель дописываются до текущей даты.
- **k = 1, α = 0.05.** Один взгляд; маркер `runtime/experiments/CAP_2026_OPENED` запрещает повтор.
- **Итог:**
  - событий < 5 → **TOO_FEW**: ни подтверждения, ни отказа, решает теневая книга;
  - нижняя граница ДИ среднего > 0 и среднее > p95 случайного контроля (200 сидов) → **CONFIRMED_2026**;
  - иначе → **NOT_SHOWN_2026**.
- Публикуется каждое событие (дата, доход, пар в корзине) и книга.

**Теневая книга** — отдельная спека, после взгляда на 2026. Её вывод не зависит от исхода 2026.
