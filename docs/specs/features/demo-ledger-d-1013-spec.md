Статус: **код 2026-10-13** (тесты написаны до кода, журнал работ — §10). Дата 2026-10-13. Родители: `autonomous-trading-roadmap-1010-spec.md`

## 1. Зачем сейчас, до этапа C

Метрика DailyRevenue v1 определена, но по демо-счёту не считается. Строить её нужно до первой
настоящей сделки:
1. ряд капитала уже идёт (снимки каждые 5 мин с 2026-10-10). Метрика по нему проверяет учёт на
   нуле: сделок нет, значит R ≈ 0 с точностью до курса USDC/USDT;
2. к этапу C учёт, сверка и отчёт будут проверены, и первая сделка попадёт в готовый контур, а не
   в недописанный.

## 3. Учёт сделок (`trader/trade_ledger.py`)

- **Источник истины — биржа:** `GET /api/v3/myTrades` по каждому символу, где после последней
  синхронизации было движение. Символы берутся из трёх мест: журнал обмена (ордера), открытые
  ордера, ненулевые балансы. Для каждого символа запоминается `fromId`.
- **Файл учёта:** `trader/runtime/trading/ledger.jsonl`, одна строка на исполнение (fill):
  `trade_id`, `order_id`, `client_order_id`, `symbol`, `side`, `price`, `qty`, `quote_qty`,
  `commission`, `commission_asset`, `time`, `is_maker`, `decision_id` (по `client_order_id` из
  журнала решений, если есть).
- **Идемпотентность:** повторная синхронизация не создаёт дублей (ключ — `symbol` + `trade_id`).
- **Комиссия в другом активе** (BNB) переводится в USDT по mid на момент исполнения. Цена берётся
  из снимка книги ближайшего времени. Источник цены пишется в строку.
- **Переводы и сбросы баланса.** Демо-счёт не даёт истории переводов. Признак сброса — скачок
  капитала между соседними снимками, который не объясняют исполнения между ними. Порог — 0.5%
  капитала после поправки на переоценку открытых позиций. Такой день получает статус `RESET`, а
  оператор может подтвердить командой.

## 4. Дневная выручка (`trader/daily_revenue.py compute`)

- **Отметка на 00:00 UTC (способ P):** снимок капитала, ближайший к полуночи, в окне ±10 мин. Нет
  такого — день `UNKNOWN` по способу P. Если способ L может восстановить отметку (позиции
  известны, цены есть), берётся L с пометкой `provenance = ledger_reconstruction`.
- **Способ L (уточнено 2026-10-13):** количества активов на начало суток (из снимка P на 00:00) +
  изменения от исполнений за сутки (база ±, котировка ∓, комиссия −) → количества на конец суток.
  Они оцениваются по ценам **того же** снимка P на конец суток. P и L различаются только тем, чего
  нет в учёте: пропущенными исполнениями, сбросом, переводом.

  Для этого снимок капитала должен хранить **количества и цены** по каждому активу. Сейчас он
  хранит только стоимость (`positions`). Добавляется поле `holdings: {asset: {qty, px}}`; старые
  снимки без него дают L = недоступно.
- **Пороги P − L:** |P − L| > 0.5% капитала → `RESET` (сброс или перевод); 0.01% < |P − L| ≤ 0.5%
  → `RECONCILE_FAIL`. Если |P − L| > 0.01% капитала, день получает статус
  `RECONCILE_FAIL` (метрика §2).
- **Статусы дня** — по метрике §3. До исполнителя C «бот жив» = доля 5-минутных снимков капитала
  за сутки ≥ 95%. После C — сердцебиение исполнителя.
- **Порог шума.** Без сделок капитал меняется только из-за курса USDC/USDT (около ±0.03%/день на
  10-10..10-13). Пока на счёте есть USDC, этот дрейф печатается отдельной строкой «вклад
  стейблкоинов» и в выручку политики не засчитывается. Выручка политики = R − вклад
  стейблкоинов.
- **Бенчмарки за те же сутки:**
  - BTC buy&hold — по дневной свече BTCUSDT с публичного API;
  - равновзвешенный торговый универсум — по дневным свечам пар со статусом `tradable` или
    `liquidity_unmeasured` из `universe.json`;
  - USDT = 0.
- **Выход** — `trader/runtime/metrics/daily_revenue.jsonl`, одна строка на сутки, полезная
  нагрузка по метрике §8. Только дозапись; пересчёт дня — новая строка с `revision`, старая не
  удаляется.

## 5. Отчёт оператору

- `trader/runtime/reports/YYYY-MM-DD.txt` — каждый день в 00:20 UTC:
  - R дня и окна 7/30/всё с ДИ и бенчмарками;
  - статус дня и число исключённых дней;
  - разложение (сделки, доля прибыльных, комиссии, проскальзывание, экспозиция);
  - вклад стейблкоинов;
  - теневые книги E7 рядом (их R по тем же суткам);
  - здоровье: доля снимков, ошибки обмена за сутки (из журнала аудита).
- Слова «растёт / падает» — только по правилам метрики §4. Иначе «рано судить».
- **Доставка — решение оператора 2026-10-13: «отчёт по сделкам предыдущего дня высылай сюда в
  9.00 утром».** Задача Claude по расписанию каждый день в 09:00 по местному времени читает
  готовый файл отчёта за вчерашние сутки UTC и присылает его в этот чат. Telegram и токен
  сигнального бота не используются.
- **Сделки предыдущего дня в отчёте:**
  - исполнения демо-счёта из учёта (до этапа C их нет, так и пишется);
  - сделки теневых книг E7 из `trader/runtime/shadow/ledger.jsonl`: монета, вход, выход, причина,
    результат после издержек, итог по книге за сутки.

## 6. Разрыв реплей ↔ факт (после этапа C)

Для суток с реальными сделками решения исполнителя прогоняются через движок E1 с моделью
исполнения. Разница R(реплей) − R(факт) публикуется в отчёте рядом с фактом (метрика §6), не
вместо него. До этапа C этот блок пишет «нет сделок».

## 7. Расписание

Задача Windows `CryptoBot_TraderDaily`, 00:20 UTC (02:20 по местному):
`trade_ledger.py sync` → `daily_revenue.py compute` → отчёт. Приоритет обычный, флаги батареи
выключены, сторож 10 мин.

Задача Claude `crypto-trader-daily-report` — каждый день в 09:00 по местному времени: читает
`trader/runtime/reports/<вчера UTC>.txt` и присылает его в этот чат. Если файла нет, пишет об этом и
проверяет журналы задачи `CryptoBot_TraderDaily`.

## 8. Требования к коду (тесты до кода)

1. **Учёт:**
   - синхронизация на поддельной бирже пишет каждое исполнение один раз;
   - повтор ничего не добавляет;
   - `fromId` продвигается;
   - комиссия в BNB переводится в USDT с источником цены;
   - `decision_id` подтягивается по `client_order_id`.
2. **Отметка на 00:00:**
   - выбирается ближайший снимок в ±10 мин;
   - нет снимка → `UNKNOWN`;
   - восстановление по L помечено `provenance`.
3. **Сверка P против L:** расхождение > 0.01% → `RECONCILE_FAIL`, день исключён из агрегатов.
4. **Сброс баланса:** скачок > 0.5% без исполнений → `RESET`; переоценка открытой позиции на
   +3% при сделке → не `RESET`.
5. **Статус `BOT_DOWN`:** доля снимков < 95% — день входит в результат счёта, но не в атрибуцию.
6. **Вклад стейблкоинов** считается отдельно; выручка политики без сделок ≈ 0 на реальных снимках
   10-10..10-13 (|R − вклад| < 0.005%).
7. **Бенчмарки:** BTC и равновзвешенный универсум на синтетических свечах дают ожидаемые числа.
8. **Только дозапись:** пересчёт дня добавляет строку с `revision + 1`, прежняя остаётся.
9. **Отчёт:** при ДИ, включающем 0, пишет «рано судить»; не пишет «растёт / падает» без ДИ.
11. **Снимок капитала** пишет `holdings` (qty и px по активу); `value()` возвращает их же.
12. **Отчёт** содержит раздел «сделки предыдущего дня» с исполнениями демо-счёта (или «нет
    сделок») и сделками теневых книг за те же сутки UTC с итогом по книге.
10. **Границы приложения:**
    - запись только в `trader/runtime/`;
    - подписанные запросы только на демо-хосты (через `exchange_client`);
    - в Telegram ничего не отправляется (доставка — в чат через задачу Claude).

## 9. Откат

Этап D только читает биржу и пишет в `trader/runtime/`. Откат: снять задачу `CryptoBot_TraderDaily`.

Ошибка, найденная на первом прогоне: при одном засчитанном дне ДИ бутстрэпа вырождается в точку

называется только при ≥ 10 засчитанных днях (`daily_revenue.MIN_DAYS_DIRECTION` = 2 блока по 5 дней).
На E1/H2/H3 не влияет: там ряды длиннее 10 дней.

Не сделано: восстановление отметки на 00:00 по способу L при пропущенном снимке (§4, §8.2) — день
без отметки сейчас `UNKNOWN`. Цена комиссии в BNB берётся по минутной свече в момент синхронизации,
а не на момент исполнения; до этапа C BNB на счёте нет, и источник цены пишется в строку.

Расписание: `CryptoBot_TraderDaily` ежедневно в 02:20 по местному (до 25.10 это 00:20 UTC, после
перехода на зимнее время — 01:20 UTC; отметка на 00:00 к этому моменту уже есть), приоритет 4,
флаги батареи выключены, сторожа 5–10 мин на шаг. Задача Claude `crypto-trader-daily-report` —
ежедневно в 09:00.
