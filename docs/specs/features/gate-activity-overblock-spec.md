- **Slug:** `gate-activity-overblock`

- **Truth-harness:** TH-04 (сопоставимые окна), TH-05 (отсутствие данных ≠ факт), TH-10, TH-12, TH-13
- **Код:** `files/pipeline_lib.py` (`recently_active_gates`, `active_over_blockers`,

- **Rollback:** вернуть коммит; поведение бота не затрагивается — меняется только
  то, какие красные флаги видит конвейер гипотез. Maximum period и shadow не

## Дефект

`analyze_blocked_gates.py` считает блоки по всему `critic_dataset.jsonl` без окна.
Гейт `entry_score` с июня ничего не блокирует (мягкий гейт RM-22 при выключенном
бандите, см. `p1-validation-0925-spec.md`), но все его 2 475 блоков марта–мая
(55 + 1 696 + 724) давали ежедневный флаг `RF_overblock_entry_score`
(miss 0.123, Sharpe 3.33). Агент L2 29.09 обосновал им все три гипотезы
(ML-порог, прогноз trend_quality, ADX фильтра боковика).

## Исправление

Гейт считается активным, если за последние 14 дней в `bot_events.jsonl` есть хотя
бы один его блок (по `reason_code` или `signal_type`). Ежедневный отчёт ставит
флаг «блокирует лишнее» только активным гейтам (неактивные — в
`inactive_over_blocking`); L2 дополнительно отбрасывает такие флаги из уже
записанных отчётов окна. Если журнал не читается — прежнее поведение (флаги не
теряются молча). На 29.09: активны 14 имён гейтов, `entry_score` — нет.
