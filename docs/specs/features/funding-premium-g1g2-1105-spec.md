# G1, G2, G3b: сбор фандинга, схождение премии, carry с плечом 2 — этап 0 без загрузки данных

Дата: 2026-11-05. Источник — пятая внешняя ревизия: гипотезы G1–G4. Решение оператора: «исследуй новые гипотезы». Трейдер
(`trader/`). Спека коммитится отдельно, до расчётов.

## 0. Зачем этап 0

Ревизия предлагает сначала скачать 1m-свечи и `premiumIndexKlines` перпов. Но правила G1 и G2 в первом приближении
считаются на том, что уже есть: 15m-свечи перпов и спота и фандинг за 2023–2025. Если гипотеза не проходит здесь, большая
загрузка не нужна. Если проходит — загрузка и уточнение идут отдельной предрегистрацией решением оператора.

Только разведка: окно 2023-03-01..2025-12-31. Хранилище 2023+ содержит перпы спотовой вселенной, «бывавшие в топ-100»;
выживаемость раскрыта. Окна 2020–2022 и 2026 не открываются.

## 1. G1: сбор фандинга вокруг начисления

- **Вселенная дня:** перпы с рангом 30-дневного оборота ≤ 100 по данным строго до дня начисления, возраст ≥ 30 дней.
- **Событие:** начисление фандинга с |ставка| ≥ порога. Пороги 0.10% и 0.30% за интервал, 2 кандидата. Время начисления
  округляется вниз до 15 минут.
- **Сделка:** сторона, получающая фандинг (шорт при ставке > 0, лонг при < 0). Вход по закрытию 15m-бара, закрывающегося
  за 15 минут до начисления; выход по закрытию бара, закрывающегося через 15 минут после.
- **Издержки:** 2 × (перп-taker 0.05% + проскальзывание корзины ранга дня, `COST_CAL`). Справочно: мейкерский вход 0.02% без
  проскальзывания на входе; это верхняя граница, потому что исполнение лимитки здесь не проверяется.
- **Отбор по ставке и причинность.** Здесь итоговая ставка неизвестна заранее, поэтому две строки:
  - **A (верхняя оценка):** порог по итоговой ставке. Это заглядывание вперёд, оно только завышает результат.
  - **B (причинная):** порог и знак ещё и по ставке предыдущего начисления той же монеты. Предыдущая ставка в момент входа
    известна.
- **Разложение** средней сделки: ценовая часть (доходность позиции без фандинга), ставка, издержки. Главный вопрос —
  съедает ли цена выплату.
- **Срезы:** корзины ликвидности B1–B4, интервал начисления (1/2/4/8 ч), годы.

## 2. G2: схождение премии перпа к споту

- **Премия бара** (приближение mark − index): close перпа · mult / close спота − 1 на одном 15m-баре. Цена перпа
  приводится к споту множителем из `funding_store.MAPPING`.
- **Сигнал:** премия на закрытии бара i выше порога: 0.4% при ранге 1–20, 0.8% при ранге 21–100. Ранг выше 100 не берётся.
  Первые 7 дней после первого бара спота или перпа исключаются.
- **Сделка:** равный номинал на ногах: шорт перпа и покупка спота по закрытию бара i + 1 (сигнал увиден, потом исполнение).
  Выход по закрытию бара, следующего за первым баром с премией ниже 1/3 порога, или через 32 бара (8 ч) от входа. По одной
  связке на монету: новый сигнал только после выхода.
- **Результат на единицу номинала:** (шорт перпа) + (лонг спота) + фандинг в (вход, выход] − издержки 2 × (спот 0.075% +
  перп 0.05%) − 4 × проскальзывание корзины.
- **Один кандидат.**
- **Срезы:** корзины, годы, премия на входе и выходе, причина выхода.

## 3. Статистика и критерий перехода (семейство, k = 3, α = 0.05/3)

- Средняя сделка, кластерный бутстрап по дням UTC, 4 000 повторов; n, σ, MDE при 80%.
- **Гипотеза идёт дальше** (к предложению загрузки и уточнения), только если одновременно:
  1. нижняя граница средней сделки > 0 после издержек; для G1 — на причинной строке B;
  2. результат не держится только на самой тонкой корзине B4: среднее без B4 > 0;
  3. положителен минимум в 2 годах из 3.
- Иначе — СТОП без загрузки.
- Верхняя оценка G1 (строка A) решения не даёт. Если даже она ≤ 0, это сильный отрицательный результат: загрузка не нужна
  при любом исходе строки B.

### 2026-11-05 — предрегистрация G2-v2 (до расчёта)

Правила G2 те же, плюс фильтры качества данных, определённые до просмотра результата v2. Доходность в отборе не участвует.
- **Пара допускается,** если |медианная премия за окно| ≤ 0.5%. Иначе спот и перп считаются разными активами.
- **Сигнал бара допускается,** если шаг цены спота / close спота ≤ порог / 4. Шаг оценивается как наименьшая положительная
  разность уникальных закрытий спота за окно.
- **Две строки:**
  - **v2-lag1** (причинная): вход по закрытию следующего бара, как в §2;
  - **v2-lag0** (верхняя оценка, нулевая задержка): вход по закрытию самого сигнального бара. Это потолок того, что могла бы дать
    мгновенная реакция на 15m-разрешении.
- **Решение:**
  - v2-lag0 ≤ 0 по среднему после издержек → G2 закрыта, минутный архив не нужен;
  - v2-lag0 > 0, а v2-lag1 — нет → эффект есть только при быстрой реакции, и предлагается загрузка 1m с новой предрегистрацией;
  - обе строки проходят критерий §3 → то же, предложение загрузки для уточнения.
- Тесты до кода: параметр задержки входа, фильтр шага цены, фильтр пары.
