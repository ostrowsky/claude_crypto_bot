## 2. Методика

### 2.1 Порядок любой проверки (протокол L3 «в деньгах», `execution-replay-e1-1010-spec.md` §7)

1. **Спека с предрегистрацией коммитится до данных:** вопрос, кандидаты (сетка фиксируется заранее), окно обучения,
   окно проверки, критерии допуска, α, контроли. Хэш коммита спеки всегда раньше хэша результата (проверяемо по
   `git log`).
2. **Тесты до кода** (`trader/test_*.py`), прогон «до кода» должен падать.
3. **Обучение (train).** Обычно 2023-03-01..2025-12-31. По предрегистрированным критериям допускаются 0..k кандидатов.
   Если допущено 0 — СТОП, проверочная половина не открывается.
4. **Проверка (test)** — один взгляд. Перед запуском пишется маркер `*_TEST_OPENED.json`; код отказывается открывать
   второй раз. Окно 2026-01-01..дата открывается только решением оператора.
5. **Отложенный период «назад» (BH19, 2018–2022)** — добавлен 2026-10-30 после аудита (§3, дефект 1).
6. **Запись результата:** журнал спеки, `trader/runtime/already_tried.jsonl`, `CLAUDE.md` и `PROJECT_CONTEXT.md`.
   Pre-commit-хук `truth_harness.py change --staged` должен пройти.

### 2.2 Дневная доходность R и интервалы

- **R_d** — изменение equity за сутки UTC, в %. Equity = кэш + позиции по закрытию 15m-бара. В `execution_replay.run`
  отметка ставится на каждой границе 00:00 UTC (`roll_days`), поэтому **дни без сделок входят в ряд с R ≈ 0**, а не
  выпадают (проверено чтением кода 2026-11-05). В дневных панелях (XSMOM, S1, TM, FC и др.) — та же функция
  агрегации.
- **Агрегат:** `trader/daily_revenue.py::aggregate(series, seed=29, alpha)`.
  - среднее R по дням;
  - ДИ — перцентильный блочный бутстрап, блоки по 5 дней подряд (`BLOCK = 5`), 2 000 повторов (`BOOT = 2000`),
    фиксированный seed 29;
  - границы берутся по индексам `int(alpha/2 * 2000)` и `int((1 − alpha/2) * 2000)`;
  - для семейства из k кандидатов α = 0.05 / k (Бонферрони). Поля называются `lo95` / `hi95` при любом α;
  - тут же считаются compound, max DD, доля положительных дней и худший день;
  - направление словами пишется только при ≥ 10 днях (`MIN_DAYS_DIRECTION`).
- **Парная разница:** `daily_revenue.paired(a, b)` — разность a − b по общим дням, тот же бутстрап.
- **Средняя сделка (LQ, CAP):**
  - LQ — `lq.trade_mean_ci`, бутстрап с блоками-днями;
  - CAP — `cap.mean_ci`, iid-бутстрап по событиям.

### 2.3 Модель исполнения (`trader/fill_model.py`)

- **Комиссии:** taker 0.10% на сторону. BNB-скидка ×0.75 = 0.075%. Режим `report` = 0.05%.
- **Проскальзывание** (`SLIP`, стоимость от середины на сторону):
  - уровень 0 — 0;
  - **уровень 1 — 8 б.п. (основной)**;
  - уровень 2 — 20 б.п.
  - Члена на размер ордера нет (`impact_k = 0`). Калибровка — два снимка демо-стакана 10-10 по 42 парам: ордер 1 000
    USDT стоил 6.6 б.п. на покупку и 10.0 на продажу (медиана), 20–23 б.п. на p90.
- **Круг на споте** при уровне 1 ≈ 2 × (0.10% + 0.08%) = 0.36%. В OB этот порог зашит как `COST_PCT = 0.36`.
- **Исполнение:**
  - рыночная покупка `p × (1 + half_spread)`, затем комиссия; продажа симметрично;
  - TP исполняется только при `high ≥ TP × (1 + tick)` — без оптимизма к очереди;
  - SL исполняется по `min(stop, open бара)` минус спред;
  - **если в одном баре задеты и TP, и SL, первым считается SL** (пессимистично).
- **Факт на демо, для сверки с моделью:**
  - EX-RL1: калибровка по 78 исполнениям, медиана 9.5 б.п.;
  - сверка «демо против бумаги»: среднее проскальзывание входа +7.0 б.п. на 85 входах, медиана 0;
  - аудит 10-30: среднее +7.8.
  - Эти цифры сняты разными способами и на разных выборках, их сопоставимость не проверялась.
- **Перпы (FC, SN, PX):** `carry.fees(level)` — спот-taker 0.10%, перп-taker 0.05% (на демо замерено 0.04%), тот же
  `SLIP`.

### 2.5 Контроли

- **Случайный контроль с той же интенсивностью:** `xsmom.matched_random` — в те же (транш, день) продаются и
  покупаются столько же случайных имён. Обычно 50 seed'ов, критерий «выше p95» = выше 48-го из 50. Аналоги:
  `carry.random_control`, `experiment_b3.random_control` (20 подвыборок), прореживание в H3/X4F (20 seed'ов).
- **PBO:** `trader/pbo.py::cscv_pbo(R, n_splits=8)` (Bailey и др., 2015). T×N матрица дневных R кандидатов, 70
  комбинаций IS/OOS. Предрегистрированное правило: PBO ≥ 0.5 закрывает строку.
- **Бенчмарки:** равновзвешенный рынок (EW), BTC buy-and-hold, 50/50, «постоянная экспозиция», FC_PASSIVE (для
  вариантов carry), X4 (для вариантов выходов на входах бота).
- **Половины и годы:** знак в обеих половинах или в большинстве лет.

### 2.6 Как формулируется вердикт (после аудита 10-30)

- **«Опровергнута»** — верхняя граница ДИ ниже значимого эффекта (или ниже нуля).
- **«Не доказана»** — нижняя граница < 0, верхняя включает экономически значимый плюс. Повторная проверка тогда
  допускается только для замороженного правила на свежих данных.
- **«Отклонена по другим причинам»** — например, ликвидации, случайный контроль, PBO, теоретический потолок.
- **Мощность** (оценка по DIR 1d): σ дневного ряда ≈ 1.6%, 828 дней → SE ≈ 0.056 %/день, минимально обнаружимый
  эффект ≈ 0.11 %/день (≈ 40 %/год). Эффекты 10–20 %/год на одном отрезке 2023–2025 не различимы.

### 2.7 Методика сигнального бота (кратко)

- **Метки:** неизменяемые later-EOD из клайнов (`files/immutable_labels.py`, `build_global_labels.py`), глобальная
  USDT-вселенная (734 пары запрошено, 530 разрешено). До 2026-08-14 использовались rolling-24h-метки того же снимка —
  это утечка (§5).
- **L3-валидаторы:**
  - `files/goal_validator.py` — дни-победители, в которые бот вошёл до пересечения +2.5%, плюс неухудшение средней
    сделки (граница −0.10 п.п.), максимальный период;
  - `files/exit_validator.py` — реплей каждой реальной 15m-сделки с 03-01, парная разница на днях-ракетах > 0, плюс
    неухудшение всех сделок, плюс согласие месяцев.
- **Разбиение:** по времени, никогда случайно; для моделей — группировка по дням (`TRAIN_DAY_GROUPED_SPLIT_ENABLED`).
- **Readouts живых изменений:** `files/readouts.py`, критерии заранее в `files/readout_registry.json`.

## 3. Известные слабые места: с них начинать поиск ошибок

Ниже то, что уже найдено и раскрыто. Аудитору стоит проверить, все ли последствия учтены, и искать похожее там, где
это не раскрыто.

1. **Правило максимального периода нарушалось** (аудит `docs/reports/2026-10-30-verdict-audit.md`). Ценовые гипотезы
   обучались только на 2023-03..2025-12, хотя спот есть с 2017-08, а перпы и фандинг — с 2020-01.
   - BH19 проверил 2018–2022 только для пяти замороженных правил: DIR_1d, TM, N8, RV, FC_PASSIVE.
   - **Остальные отклонения на трейне по-прежнему опираются на один рыночный режим** (альты −51% к BTC): XSMOM, S1,
     FC-select, FS, MD-B/MD-U, LA, SN, RB, LQ, FC-W, PX, OB.
   - CAP — исключение: решающее окно у него 2018–2022.
   - Есть ли архив `bookDepth` раньше 2023-01 — **не проверено**: загрузка начиналась с 2023-01-01.
2. **Проверочное окно 2026 использовано многократно.** Отдельными однократными взглядами на 2026 судились: FC_PASSIVE,
   N8, QB_T0, RV_mom_56, CAP_W4_X50_H24, E8 (09-26..10-19), F2 (07-01..10-20), B3, H3, «удержание на
   RSI-дивергенции» (07–10).
   - Каждый взгляд k = 1 внутри своей спеки, но **поправки на число взглядов по программе в целом нет**.
   - Единственный принятый на 2026 результат (FC_PASSIVE) подтверждён также на 2020–2022 (BH19).
3. **Множественные сравнения по программе.** Около 40 гипотез и сотни кандидатов. Бонферрони действует только внутри
   семейства одной спеки.
4. **Переиспользованная проверочная половина.**
   - H3: «test half not fresh» — раскрыто в записи.
   - Удержание на RSI-дивергенции: сетка кандидатов писалась после того, как была видна таблица за весь период —
     раскрыто, поэтому вывод отдан в теневой readout.
5. **Изменения после того, как был виден результат** (все раскрыты, проверьте, нет ли нераскрытых):
   - B2: порог сверки генератора 0.80 → 0.79 решением оператора после результата 0.790;
   - LQ: первый прогон использовал среднее дневных средних вместо предрегистрированной средней сделки. Исправлено с
     раскрытием, файл первого прогона сохранён (`LQ_TRAIN.run1_daily_mean_estimator.json`);
   - PX: окно корреляции сдвинуто на 5 дней **до** любого прогона — коммит c305d2f раньше результата c0a5a0e;
   - XSMOM: первый прогон невалиден (бенчмарк на 10k USDT упирался в минимум 10 USDT), сохранён как
     `XSMOM_TRAIN.invalid_ewu_scale.json`;
   - F2: у правила delta не было минимума изменённых сделок — раскрыто;
   - QB: почти одинаковые T0 и T5 делают PBO ≈ 0.5 по построению — раскрыто как дефект предрегистрации;
   - CAP: 2018–2019 почти пусты (< 50 USDT-пар) — раскрыто до проверки.
6. **Выбор вселенной заглядывает вперёд.**
   - OB: 30 пар выбраны по частоте входа в топ-30 по обороту за весь период 2023–2025 (раскрыто в спеке §2);
   - вселенная BH19 — 418 пар, стейблкоины и фиат исключены;
   - XSMOM/S1 — 668 пар, включая делистинговые; вселенная дня — по строкам < d.
7. **Модель издержек одна для всех пар:** 8 б.п. на сторону. Для BTC/ETH это, вероятно, завышение (замеренный спред
   ETH 0.04 б.п.), для мелких альтов — возможно, занижение. Влияние на знак вывода по каждой гипотезе **не
   проверено** (дефект 3 аудита 10-30).
8. **Грубые контроли.**
   - p95 из 50 случайных портфелей — это 48-й из 50, большой шум у границы. RV на трейне прошёл с запасом +0.0013 к
     p95.
   - PBO при N = 2..4 кандидатах и 70 сплитах — грубая оценка.
9. **Малые выборки проверки:**
   - E8 — 24 дня;
   - CAP 2026 — 2 события;
   - X4 демо — 80 сделок;
   - на 5-дневных блоках при < 30 днях ДИ ненадёжен.
10. **Carry-движок:**
    - ликвидация проверяется раз в сутки по дневному high относительно цены входа, без внутридневной
      последовательности. Учитывает ли цена входа доливку маржи — не проверено;
    - фандинг на демо — плоский 0.0001, не живой. Поэтому демо-деньги FC — только проверка механики.
11. **Делистинг в событийных сделках** (LQ/CAP) приравнен к −50%. Это допущение, не измерение.
12. **Сигнальный бот:** кандидаты в E1 — только события бота, прошедшие его гейты (TH-06: «проверять гейт на входах
    самого бота»). Генератор B2 воспроизводит правила входа с полнотой 0.790. Гейты (ML, ранкер, бандит, guard'ы,
    кулдауны) он не воспроизводит.
13. **Утечки в ранних метриках бота** (до августа 2026) найдены и исправлены. Числа до 2026-08-13 с новыми не
    сравниваются (§5).
